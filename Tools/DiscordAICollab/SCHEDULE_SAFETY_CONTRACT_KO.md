# 예약·사용량·종료 제어 계약 (2026-10-23)

기존 협업 DB에 별도 예약/사용량 관측/모의 실행 표를 추가합니다. 기존 업무·승인·사용량 이력은 유지합니다. Asia/Seoul 고정, 정리 기본 10분, 실제 실행 90초가 정리 시작 전에 끝날 때만 시작합니다. 마감 전 접수·실행 차단은 공통 트랜잭션 게이트로 적용합니다. 취소는 예약을 취소할 뿐 기존 수동 정지·미술 HOLD를 해제하지 않습니다.

이번 모드 SIMULATION_ONLY: 실제 종료, 병합, OS 작업 등록, 추가 AI 호출을 실행하지 않습니다. Windows Task Scheduler XML은 고정된 로컬 tick 진입점만 참조하며 임의 명령을 받지 않습니다. PC 완전 종료 시 재개 불가, 로그인/실행 중 서비스가 필요합니다.

공식 사용량 조회 결과는 출처·관측 시각·5시간/주간 창과 회복 시각만 저장합니다. 현재 앱 전용 공식 도구는 독립 Discord 봇에 자동 제공되지 않으므로 자동 갱신 미연결 상태에서는 UNKNOWN/HOLD입니다. 회복 시각 경과를 사용 가능으로 추정하지 않고 새 관측이 필요합니다. 재개는 유효한 기존 승인·미실행 상태·시간 여유·주일 아님·동시2 이내 조건을 모두 만족해야 합니다. 소비된 슬롯/결과불명/실행중 작업은 자동 재시도하지 않습니다.

마감은 접수 중단·신규 실행 차단·진행중 안전 종료 대기·미실행 업무 보류 목록·완료/미검증 목록을 기록합니다. 외부 실행 중 강제 종료나 상태 위장은 금지합니다. 기존 CLI90초 한도를 유지합니다.

종료는 특정 예약별 대표 Discord ID 승인과 별도 로컬 재확인을 요구하는 설계입니다. 동기화/보호/Unity/파일복사/미저장 작업/예약 충돌/Discord 최종 보고의 최신 검증을 모두 요구하며 하나라도 UNKNOWN이면 HOLD입니다. 현재 모든 종료 요청은 모의 평가만 수행하고 시스템 API를 호출하지 않습니다. 통합 승인과 실제 통합 어댑터도 미연결이므로 제품 통합은 HOLD입니다. shutdown.exe는 timeout 설정 시 강제 종료가 암묵 적용될 수 있어 사용하지 않습니다. 향후 Windows 공식 비강제 API와 취소 유예를 별도 검증해야 합니다.
