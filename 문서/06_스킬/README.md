# 스킬

2026-10-12 Chapter3 확정 기획은 [스킬 상점·강화·냉기 설계](Chapter3_스킬상점_강화_냉기_동결괴사_20261012.md)를 따른다. 탈렌트 구매/원스킬 대체·부활·정화 Ⅱ·한기 해제는 **미래 설계이며 현재 구현15스킬에 추가하지 않았다**.

## 목적

직업별 실제 전투 스킬의 데이터, 실행, 상태효과와 검증 상태를 관리한다.

## 상태

**현재 구현 정본.** 수호자 3개(도발·철벽·수호의 맹세), 치유사 3개(치유의 빛·회복의 파동·정화), 사수 3개(정조준·화살비·동료의 습격), 투사 3개(난도·회심의 일격·회오리 베기), 마도사 3개(파이어 볼·썬더볼트·가이아 웰)가 `BattleSkillCatalog`와 실행 코드에 연결되어 있다. 직업 패시브 프리뷰와 미래 상태·Talent 스킬은 [미구현/향후 후보](미구현_향후_후보.md)에 별도로 보존한다.

## 구현 구조

- `JobDefinition.StartingSkills`: 캐릭터 생성 프리뷰와 안정적인 Skill ID 제공
- `BattleSkillCatalog`: 프리뷰를 전투 메뉴용 정의로 변환하고 실제 구현 여부·효과·쿨타임·지속값 연결
- `BattleSkillExecutor`: 사용 가능 여부와 효과 실행 담당
- `BattleSkillCooldowns`: 참가자별·스킬별 쿨타임을 해당 참가자의 행동 차례 기준으로 관리
- `BattleStatusEffectRuntime`: 도발과 대상별 화상 잔여 횟수·저장 피해, 감전 1·침묵 1, 가이아 웰·철벽, 수호의 맹세의 수호자·이전 예산 관리
- `BattleFighterResourceRuntime`: 참가자별 기세와 난도 스킬 직접 사용 횟수를 서로 분리해 관리
- `BattleSceneController`: 현재 행동자의 직업 스킬 메뉴, 입력, HUD 표시 연결
- `BattleActionPresenter`: 계산과 분리된 공용 스킬 강조 연출

## 현재 전투 상태의 경계

| 분류 | 현재 구현 | 직접 피해·DoT와의 관계 |
|---|---|---|
| 해로운 상태 | 독·맹독(공용 Poison 분류), 화상, 감전, 침묵 | 독·화상은 대상 행동 종료의 DoT, 감전은 다음 행동의 주는 직접 피해를 15% 감소, 침묵은 다음 성공 행동까지 Skill 명령 차단 |
| 이로운 방어 | 공용 방어, 철벽, 가이아 웰, 수호의 맹세 | 공용 방어와 철벽·가이아 웰은 중첩하지 않음. 수호의 맹세는 직접 전투 피해만 보호하고 DoT는 제외 |
| 행동·자원 | 도발, 기세 0~3, 스킬별 쿨타임 | 도발은 단일 적대 대상 변경. 기세와 쿨타임은 해로운 상태가 아니며 정화 대상이 아님 |
| 길 특성 | 집중, 잔향 포착, 패턴 익히기, 굳건한 자리, 회복탄력 | 직접 피해·직접 치유에 적용. 독·화상 DoT 피해에는 길 배율을 적용하지 않음 |

독의 기본형은 최대 HP 5%×3, 맹독은 7%×3이다. 한 대상에는 독 상태 하나만 남으며 강도에 따라 교체·갱신한다. 공용 방어는 직접 피해를 절반으로 줄이고, 철벽은 70%, 가이아 웰은 60%를 각각 줄인다. 자세한 계산 순서와 수호의 맹세 예산은 [전투 정본](../10_전투/전투시스템.md)을 따른다. `HarmfulStatusType`의 Poison·Burn·Shock·Silence는 정화 한 번으로 함께 제거된다.

### 공용 침묵 상태

- 살아 있는 참가자에게 적용·재적용할 수 있으며 한 대상에 `침묵 1`만 유지한다. 현재 침묵을 부여하는 신규 몬스터·스킬은 없다.
- 대상의 다음 성공한 실제 행동 동안 모든 Skill 명령을 차단한다. 기본 공격·방어 등 다른 정상 명령은 가능하고, 행동 완료 때 침묵을 제거한다. 메뉴·대상 선택 취소와 잘못된 입력은 행동 완료가 아니므로 제거하지 않는다.
- 스킬 버튼은 흐린 색으로 표시하되 포커스·클릭을 유지하여 `침묵 상태에서는 스킬을 사용할 수 없습니다.`라고 안내한다. 차단 입력은 행동·턴·MP·쿨타임을 소비하지 않는다. 정화도 Skill이므로 침묵한 치유사는 자기 침묵을 정화할 수 없다.
- 피해·DoT·민첩·대상 판정·Path 특성에 관여하지 않고 방어·도발·버프·기세·쿨타임과 독립적으로 유지한다. 전투불능과 전투 종료 시 다른 전투 Runtime 상태처럼 정리한다.
- 상태 HUD와 상세 팝업은 `침묵 1` 텍스트와 `다음 행동에서 스킬을 사용할 수 없습니다.` 설명을 사용한다. 적절한 기존 아이콘이 없어 현재 배지는 텍스트 fallback이다.

## 현재 구현 스킬

### 수호자 도발 (`guardian_taunt`)

- 적 전체에 적용
- 적마다 다음 2회 실제 행동을 독립적으로 추적
- 단일 적대 행동의 대상을 수호자로 강제하며 일반 Target Range보다 우선
- 광역 공격과 비적대 행동에는 영향 없음
- 수호자 전투불능 시 해제
- 수호자 자신의 행동 기준 재사용 대기시간 3턴
- 적 HUD에 `도발 2`, `도발 1` 표시
- 3대3에서는 슬라임 세 개가 상태를 각각 보관하고 자기 행동 완료 때만 남은 횟수를 소모

### 치유사 치유의 빛 (`healer_healing_light`)

- 자신을 포함한 같은 진영의 살아 있는 아군 1명을 선택
- 적과 전투불능 아군은 선택 불가하며 부활 효과 없음
- 대상 최대 HP의 35%를 올림 정수로 회복하고 최대 HP를 초과하지 않음
- 최대 HP 대상은 선택할 수 있지만 안내 후 행동을 소비하지 않고 스킬 메뉴로 복귀
- 스킬 데이터의 `MaxHpHealRatio=0.35`를 사용하며 1차 구현에는 별도 쿨타임 없음
- PVFX Foundry 0.3.0 Radiant Heal grid 96×96 14프레임을 대상 위치에서 50ms 간격으로 재생
- manifest `peak`인 7프레임에서 실제 회복과 `+회복량`, HP HUD·상세 팝업 갱신 실행
- 대상 선택 중 Esc/취소는 스킬 메뉴, 스킬 메뉴 Esc/취소는 기본 명령으로 복귀

### 치유사 정화 (`healer_cleanse`)

- 자신을 포함한 같은 진영의 살아 있는 아군 1명을 선택하며 전투불능 아군은 선택 불가
- 대상의 현재 독·화상·감전·침묵을 한 번에 모두 제거하고 HP는 회복하지 않음
- `HarmfulStatusType`과 공통 조회·제거 API가 기존 독 Dictionary·화상 Dictionary·감전 HashSet 위에서 작동
- 방어·가이아 웰·도발·기세·쿨타임은 해로운 상태 목록에 등록하지 않아 제거하지 않음
- 대상에게 해로운 상태가 없으면 `정화할 해로운 상태가 없습니다.` 안내 후 행동·턴·쿨타임을 소비하지 않고 스킬 메뉴로 복귀
- 치유사 자신의 행동 기준 재사용 2턴이며 다른 참가자 행동에는 감소하지 않음
- PVFX Foundry `spectral-bloom` 96×96, 16프레임을 20 FPS로 대상 위치에서 재생하고 release index 7에서 모든 상태 제거와 HUD 갱신
- 버튼과 상세 팝업 아이콘은 같은 시트의 peak index 5 고정 Sprite를 사용하고 실제 연출은 전체 16프레임과 분리
- 향후 출혈·저주·마비는 저장 로직을 구현한 뒤 `HarmfulStatusType`과 공통 조회·제거 분기에 등록하면 같은 정화 실행 흐름을 재사용

### 사수 정조준 (`sharpshooter_aim`)

- 강한 단일 원거리 물리 공격
- 기존 `TargetResolver`의 원거리 규칙을 사용해 후열 생존 시 후열만, 후열 전멸 후 전열만 선택
- 기본 공격력의 160%를 정수 퍼센트 올림으로 계산: `(Attack×160+99)/100`
- Projectile 도착 시 기존 `TakeDamage`를 호출하므로 방어 50%를 유지하고 방어 무시·치명타·상태이상 없음
- 사수 자신의 행동 기준 재사용 2턴: 사용 직후 2, 다음 사수 행동 1, 그다음 사용 가능
- `정조준!` 강조 뒤 기존 golden_arrow를 0.42초 동안 이동하고 도착 순간 피해·HP HUD·피격 연출 갱신
- 대상 선택 중 Esc/취소는 스킬 메뉴, 스킬 메뉴 Esc/취소는 기본 명령으로 복귀

### 사수 화살비 (`sharpshooter_arrow_rain`)

- 스킬 범위 `EnemyRearRowAll`로 살아 있는 적 후열 전체만 공격하며, 후열이 비어도 전열로 전환하지 않음
- 후열 대상이 0명이면 안내 후 Projectile과 행동을 시작하지 않고 스킬 메뉴 유지
- 각 후열 대상에 일반 공격의 120%를 정수 올림으로 계산하고 `TakeDamage`의 기존 방어 50% 유지
- Kenney `bow` 아이콘과 기존 Polar_34 `golden_arrow` 8프레임을 원본 수정 없이 재사용
- 짧은 조준→화살 3발 상승→0.16초 대기→대상마다 장식 화살 3발 낙하→공유 타격→동시 피격 순서로 약 0.75초 재생
- 장식 Projectile 수와 피해 횟수를 분리하여 대상마다 실제 120% 피해는 한 번만 적용
- 모든 피격 반응까지 끝나 사용 성공이 확정되면 사수 자신의 행동 기준 2턴 쿨타임 시작. 후열 0명 거절에는 쿨타임 없음
- 정조준과 화살비는 같은 `BattleSkillCooldowns`를 사용하지만 Skill ID별로 독립 저장되어 서로의 남은 턴을 변경하지 않음

### 사수 동료의 습격 (`sharpshooter_companion_attack`)

- 사수 전용 야수 동료 `BeastCompanion`이 등장해 지정 적을 공격하는 스킬이며 일반 파티 동료 `Companion`과 별도 시스템
- `BeastCompanion`은 별도 `Combatant`가 아니므로 HP, 독립 턴, Formation 슬롯이 없고 공격 대상이 되지 않음
- 살아 있는 적 1명을 전열/후열 구분 없이 선택하되 단일 적대 행동이므로 공용 `TargetResolver`의 도발 강제 대상을 우선
- 기본 공격의 180%를 정수 올림으로 계산하고 접촉 순간 `TakeDamage()`를 호출해 기존 방어 50% 감소 유지
- 사수 자신의 행동 기준 3턴 쿨타임이며 다른 스킬 쿨타임과 Skill ID별로 독립
- 1차 구현은 기본 Wolf가 매 사용 시 현재 행동 중인 사수 `ActionRoot`의 실제 위치·표시 크기에서 계산한 근처 지점에서 출발해 대상 바로 앞까지 돌진하며, 최초 구현 이동 속도의 3/4(570 UI 단위/초)을 사용
- 전투 Run은 384×40 원본을 64×40의 서로 다른 6개 Sprite로 런타임 분할하고, 별도 Coroutine이 12 FPS로 0→1→2→3→4→5→0 순환한다. 위치를 바꾸는 Transform Coroutine과 독립적으로 동시에 실행하므로 Formation이나 표시 위치가 달라져도 사수 옆에서 다리를 움직이며 달린다.
- 대상 바로 앞 도착 순간에만 피해를 적용하고 Wolf가 관통하지 않고 잠깐 멈춘 뒤 제거되며, 피격·제거 완료 뒤 다음 턴 진행
- `BeastCompanionCatalog`가 `BeastCompanionDefinition`을 제공하므로 `BattleSceneController`에는 Wolf 경로가 없고 향후 Bear/Fox 장착 데이터로 교체 가능
- 아이콘은 Wolf Run 원본 SpriteSheet에서 작은 버튼에서도 몸통·머리·꼬리·다리가 비교적 잘 구분되는 다섯 번째 프레임(index 4)을 런타임에 잘라 고정 표시하며 원본 PNG는 수정하지 않음. 전투 연출은 이 고정 아이콘 Sprite가 아니라 별도로 만든 6개 Run Sprite 전체를 사용한다. 경로와 프레임 번호는 `BeastCompanionDefinition`이 제공하고 정조준은 기존 Kenney `target.png` 유지
- 야수별 기본 피해를 크게 차등화하지 않고 패시브 성향과 플레이 스타일을 선택의 중심으로 유지
- 야수 선택 UI, 장착·저장과 패시브 적용은 미구현. 확정 수치와 Monster Pet 확장 방향은 [사수 BeastCompanion 확장 설계](../10_전투/사수_BeastCompanion_확장_설계.md)를 따른다.

### 투사 난도 (`fighter_slash_stack`)

- `난도`는 스킬 이름이며, 공격 적중 후 얻는 투사 개인 전투 자원 이름은 `기세`
- 기존 근거리 `TargetResolver` 규칙으로 살아 있는 적 1명을 선택해 일반 공격 피해의 150%를 가함
- 기존 근거리 기본 공격 연출을 재사용하며 실제 타격 순간 피해를 적용한 뒤 자신에게 기세 +1
- 기세가 이미 3이면 `기세가 이미 최대입니다.` 안내 후 행동과 쿨타임을 소비하지 않음
- 난도 스킬의 성공한 직접 사용을 별도로 세며, 세 번째 직접 사용 때 투사 행동 기준 2턴 쿨타임 시작
- 기세가 3이라는 사실 자체는 쿨타임 조건이 아니며 회심의 일격으로 기세를 소비해도 난도 쿨타임은 유지
- 난도 버튼은 `cross`, 기세 상태는 `skull` 아이콘 사용

### 투사 회심의 일격 (`fighter_finishing_strike`)

- 기존 근거리 `TargetResolver`와 전진·타격·피격·복귀 Presenter를 재사용하는 단일 근거리 물리 공격
- 타격 순간 기세 0/1/2/3을 일반 공격의 100/130/160/190%로 변환해 정수 올림 피해 적용

## 구현과 검증의 경계

현재 시작 스킬 15개는 구현되어 있다. 실제 입력과 연출의 남은 Play Mode 확인 항목은 `CURRENT_STATUS.md`를 따른다. `BattleSkillCatalog`는 미구현 프리뷰 ID가 들어오면 메뉴에 `[미구현]`으로 표시하고 실행하지 않는다. 이것은 현재 15개가 미구현이라는 뜻이 아니다.

전투 대상 선택 UI는 적·아군 후보 목록을 모두 받을 수 있게 분리되어 있다. 공격은 `TargetResolver`의 적대 사거리 후보를, 치유의 빛은 같은 Formation의 `LivingMembers`를 전달하므로 향후 단일 아군 버프에도 같은 입력 흐름을 확장할 수 있다.

스킬 설명 팝업은 스킬 메뉴에서 Hover하거나 키보드 포커스한 동안만 표시한다. 스킬 확정 즉시 모든 스킬이 공통 `CloseSkillInspectionForAction` 경계를 통과해 메뉴·Hover·포커스·팝업을 닫고, 대상 선택과 실제 연출 및 행동 종료 뒤 기본 명령 화면에서는 숨김을 유지한다. 다음 스킬 메뉴에서 새 Hover/포커스가 생길 때만 다시 표시한다.
