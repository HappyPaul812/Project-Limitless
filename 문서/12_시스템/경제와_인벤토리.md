# 경제와 인벤토리 최소 기반

## 공통 구조

- 화폐는 `EconomyService`, 아이템 보유량은 `InventoryService`가 현재 세션 값을 관리한다. 화폐는 음수와 int overflow를 허용하지 않으며 지출 실패 시 잔액을 변경하지 않는다.
- 사용자에게 보이는 화폐 단위는 항상 **탈렌트**다. 내부 저장/API는 범용 기술명 Currency를 유지하고, 화면 문자열·아이콘·금색 tint는 `CurrencyPresentation`에서 공통 제공한다.
- 공용 아이콘은 Kenney Board Game Icons의 `token.png`를 사용한다. 흰색 원형 토큰을 `CurrencyPresentation.IconTint`로 금색 표시하며 상점·퀘스트 보상·인벤토리 UI가 같은 Sprite 참조를 재사용한다.
- 아이템 저장 키는 표시 이름이 아닌 stable `ItemId`다. `ItemDefinition`은 DisplayName, Description, Category, MaxStack, BuyPrice, SellPrice, Icon, ItemUseType을 제공하고 모든 시스템은 `ItemCatalog`로 조회한다.
- Inventory JSON은 사람이 확인 가능한 `ItemId + Count` 배열이다. Asset 전체를 저장하지 않아 이름·설명·아이콘 변경이 기존 저장을 깨지 않는다.
- `RewardBundle`은 EXP, Currency, ItemReward를 사전 검증한 뒤 함께 적용한다. EXP는 기존 `ExperienceProgression`을 재사용한다.
- 현재 가방 용량은 제한하지 않는다. TODO: 은행/가방 설계 시 Inventory Capacity 확정.

## 확정 경제 방향

- 몬스터 사냥은 소액 수입, 퀘스트 완료는 상대적으로 큰 수입을 지향한다.
- 상점은 소비품과 장비 구매 수단이지만 구체 지급량과 가격은 아직 확정하지 않는다.
- 필수 스토리가 돈 부족으로 막히거나 반복 사냥을 강제하는 구조를 피한다.
- 패배해도 화폐를 잃지 않는다. 휴식 경험치는 없다.
- 은행은 화폐 예금이 아닌 아이템 창고 역할이며 이번 기반에는 포함하지 않는다.
- World EXP HUD에는 화폐를 표시하지 않는다.

## 시작 마을 잡화상 1차

- `ShopDefinition`은 상점 ID와 판매 ItemId만 보관하고, 공용 `ShopPresenter`가 화면을, `ShopService`가 원자적 거래를 담당한다.
- `shop_general_starter_village`는 회복약(`item_healing_potion_small`, 구매 20/판매 10)과 마력 회복약(`item_mana_potion_small`, 구매 30/판매 15)을 판매한다. 거래 수량은 사용자가 선택하며 기본값과 아이템 전환 시 값은 1이다.
- 구매 최대는 현재 탈렌트로 살 수 있는 수량과 남은 MaxStack/향후 Capacity 수용량 중 작은 값, 판매 최대는 현재 보유량이다. 구매/판매 모드별 `-`·`+`·`최대` 조작과 선택 수량 기준 총액을 제공하며 실행 버튼 문구는 `구매`/`판매`다.
- `InventoryService`도 `ItemDefinition.MaxStack`을 실제로 강제한다. UI와 공용 API가 같은 제한을 사용하므로 향후 보상이나 퀘스트가 상점 제한을 우회하지 못한다.
- `ShopService`는 Shop 판매 여부·양수 수량·long 기반 총액 overflow·자금·Stack·보유량을 모두 사전 검증한 뒤 수량 전체를 원자적으로 거래한다.
- 가격·설명·아이콘·향후 효과 미리보기(HP +30/MP +12)는 `ItemDefinition` 데이터에서 읽는다. 실제 아이템 사용 효과는 아직 구현하지 않는다.
- 신규 캐릭터 시작 화폐는 0을 유지한다. 거래 성공 시에만 현재 슬롯을 저장하고 UI 단순 갱신에는 디스크 저장을 수행하지 않는다.
- 상점은 `CurrencyPresentation`의 탈렌트 이름과 공용 금화 아이콘을 사용한다. 아이템 아이콘은 Kenney Board Game Icons CC0의 `flask_full`/`flask_half`를 프로젝트 전용 Sprite로 복사해 빨강/파랑 tint 데이터로 구분한다.
- 상점이 열리면 World EXP HUD와 플레이어 이동을 소유자 기반으로 억제하고, 닫기·NPC 소실·Scene 전환·InteractionSystem 비활성화 때 모두 복귀한다. 장비상·은행·아이템 사용은 아직 미구현이다.

## 저장 호환과 검증

Version 1에 선택 필드 Currency와 Inventory를 추가했다. 구버전 JSON에서 필드가 없으면 JsonUtility 기본값인 0/null을 화폐 0·빈 Inventory로 복원하며 기존 Player, Level/EXP, Path, Job, Position, PartyResources는 유지한다.

`Project Limitless/Test/Economy Inventory Audit`에서 ItemDefinition ID/가격/MaxStack, Shop ItemId·중복·판매가 규칙, 잡화상 다중 구매 200→140→20, 회복약 2개 판매 20→40, 부족 구매·초과 판매의 무변경, 가격×수량 overflow와 Inventory MaxStack 강제를 검사한다. JSON 왕복과 구버전 누락 필드도 유지한다.

## 월드 소지품과 소비 아이템

- `ItemDefinition`의 `ItemEffectType`과 `EffectAmount`가 실제 효과를 정의한다. 회복약은 월드 단일 대상 HP +30, 마력 회복약은 MP 사용자 단일 대상 MP +12이며 UI나 ItemId 분기에 수치를 복사하지 않는다.
- `ItemUseService`가 보유·정의·월드 사용 가능 여부·대상·효과 조건을 검증한 뒤 `PartyResourceService`에 효과를 적용하고 1개를 소비한다. 실패하면 수량을 소비하지 않는다.
- HP/MP는 최대치를 넘지 않고 실제 회복량을 반환한다. 최대치 대상, HP 0 대상, MP 미사용 대상에게는 사용할 수 없다. 일반 회복약은 부활 기능을 겸하지 않는다.
- 월드와 필드에서 `I`로 소지품을 열며 Count 0은 숨기고 빈 목록에는 `보유한 아이템이 없습니다.`를 표시한다. 대상은 현재 3인 전투 구성의 실제 아군 목록에서 가져오며 UI에 멤버 이름을 고정하지 않는다.
- 소지품은 기존 World EXP HUD 억제와 플레이어 이동 잠금을 재사용한다. `WorldModalState`가 Dialogue·Shop·Inventory의 단일 소유자를 관리해 둘 이상의 Modal이 동시에 열리지 않게 한다.
- 성공 시 현재 저장 슬롯에 Inventory와 PartyResources를 함께 저장한다. 필드 회복값은 `PartyResourceService`에 남아 다음 Battle 시작값으로 사용된다.
