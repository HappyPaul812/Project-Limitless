# 경제와 인벤토리 최소 기반

## 공통 구조

- 화폐는 `EconomyService`, 아이템 보유량은 `InventoryService`가 현재 세션 값을 관리한다. 화폐는 음수와 int overflow를 허용하지 않으며 지출 실패 시 잔액을 변경하지 않는다.
- 아이템 저장 키는 표시 이름이 아닌 stable `ItemId`다. `ItemDefinition`은 DisplayName, Description, Category, MaxStack, BuyPrice, SellPrice, Icon, ItemUseType을 제공하고 모든 시스템은 `ItemCatalog`로 조회한다.
- Inventory JSON은 사람이 확인 가능한 `ItemId + Count` 배열이다. Asset 전체를 저장하지 않아 이름·설명·아이콘 변경이 기존 저장을 깨지 않는다.
- `RewardBundle`은 EXP, Currency, ItemReward를 사전 검증한 뒤 함께 적용한다. EXP는 기존 `ExperienceProgression`을 재사용한다.
- 현재 가방 용량은 제한하지 않는다. TODO: 은행/가방 설계 시 Inventory Capacity 확정.

## 확정 경제 방향

- 몬스터 사냥은 소액 수입, 퀘스트 완료는 상대적으로 큰 수입을 지향한다.
- 상점은 소비품과 장비 구매 수단이지만 구체 지급량과 가격은 아직 확정하지 않는다.
- 필수 스토리가 돈 부족으로 막히거나 반복 사냥을 강제하는 구조를 피한다.
- 패배해도 화폐를 잃지 않는다. 휴식 경험치는 없다.
- 은행은 화폐 예금이 아닌 아이템 창고 역할이며 이번 기반에는 포함하지 않는다.
- World EXP HUD에는 화폐를 표시하지 않는다.

## 저장 호환과 검증

Version 1에 선택 필드 Currency와 Inventory를 추가했다. 구버전 JSON에서 필드가 없으면 JsonUtility 기본값인 0/null을 화폐 0·빈 Inventory로 복원하며 기존 Player, Level/EXP, Path, Job, Position, PartyResources는 유지한다.

`Project Limitless/Test/Economy Inventory Audit`에서 ItemDefinition ID/가격/MaxStack, 화폐 0→100→125·200 지출 실패·20 지출 성공=105, 아이템 0→3→2·초과 제거 실패, JSON 왕복과 구버전 누락 필드를 검사한다.
