## ACL·쓰기·다른 점유 가능성

현재 새 빌드 root·artifacts/Probe·native 중간 폴더의 DACL은 상속 Allow, 명시Deny0이며 관리자 full/Authenticated Users modify가 관측됩니다. 기존 빌드가 하위 폴더·DLL·native PDB를 생성한 근거도 있어 출력 폴더의 포괄적 쓰기 권한 부족을 뒷받침하는 증거는 없습니다. 그러나 실패 당시 exe의 고유 ACL은 파일 부재로 확인 불가이며 현재 DACL만으로 당시 유효 권한을 완전히 인증하지 않습니다. 별도 쓰기 시험 파일을 만들거나 ACL을 변경하지 않았습니다.

MSB3021의 원문은 source access denied이며 명시적 sharing-violation32 기록은 아닙니다. V3 filter/파일 검사·다른 process 점유·삭제/격리 등 가능성을 열어 둡니다. 실패 시점 HANDLE trace가 없고 현재 exe가 없으므로 과거 점유자를 사후 확정할 수 없습니다. 현재 전체 HANDLE 검사나 PID4 조회를 반복하지 않았습니다.
