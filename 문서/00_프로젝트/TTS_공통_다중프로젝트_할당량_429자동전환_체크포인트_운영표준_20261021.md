# LIMITLESS TTS 공통 운영 표준 — 다중 프로젝트 Quota·HTTP 429 Failover·체크포인트·일일 재개

**버전:** v1 / 2026-10-21
**상태:** **운영 로직의 실사용 검증 완료(세린·태온 배치)** / **범용 엔진 코드 리팩터링은 미실행**
**책임:** TTS 담당(제작·로그·음성 QA), Codex(필요시 공통 엔진 구현·테스트·Unity 통합), 대표(캐스팅/과금/게임 적용 승인)
**적용:** LIMITLESS의 다른 캐릭터, 내레이션, 추가 챕터, 필요시 다른 Gemini TTS 배치. **하렌의 제작 보류 지시는 이 문서로 변경되지 않음.**
**우선순위:** 당일 사용자 승인·공식 API/Quota 정책 → 해당 모델·Project 실제 정보 → 본 공통 로직 → 구 버전의 개별 실행 설명. 과거 작업 이력/사용 키 수를 새 할당량으로 오인하지 않는다.

> **재사용 대상은 운영 알고리즘과 안전 계약이다.** 현재 실사용 파일 `Renewal_Auto_TTS_Failover_v2.py`는 세린·태온의 기존 152개 manifest·디렉터리에 맞춰 작성되었으며, **별도 캐릭터에 그대로 돌릴 수 있는 범용 TTS 실행기로 검증된 것은 아니다.** 이후 담당자는 신규 manifest/폴더/목소리만 바꾸는 공통 엔진으로 리팩터링하거나, 기존 프로그램에 **프로젝트 및 캐릭터별 별도 작업 공간과 테스트**를 추가해야 한다.

## 1. 도입 목적과 실제로 입증된 사례

기존 1-Key 429 → 전체 HOLD 방식에서 발생하던 불필요한 작업 정지를 줄이되, 별도 Google 프로젝트라는 사실과 별도 할당량이 **실제로 검증된 경우에만** 제한된 범위의 자동 전환을 허용한다. 다른 키를 **무작정 돌려가며 같은 프로젝트의 quota를 우회하는 방법이 아니다.**

**실사용 관측 사실(사용자 PowerShell 화면, PT 2026-10-21):**

1. `main20_confront_serin_02` 합성에 `KEY3` 사용 중 **HTTP429** 발생. 당시 로컬 시도 **35/40**, READY **60/152**, 원 스크립트가 `HOLD.json` 및 `RUNNING.lock` 기록.
2. `Renewal_429_SameDay_Switch_v2.py`로 기존 429 증거를 `recovery_snapshots`에 보존하고 `PROJECT_3` 격리. SHA·DialogueID/기존 WAV 일치검증과 사용자 `SWITCH429` 수동 승인이 선행됨.
3. 개선한 `Renewal_Auto_TTS_Failover_v2.py`가 **KEY4**로 같은 `main20_confront_serin_02`을 제작 성공, 누적 **61/152**, 로컬 시도 **36/40**, `HOLD=False`, 격리 `PROJECT_3` 유지.
4. 이후 로컬 사용 한도까지 진행: `KEY1=10, KEY2=10, KEY3=9, KEY4=10` → 합계 **39/40**, 잔여 로컬 예산 **1**이지만 **정상 안전 종료** `[GROUP/KEY CAP]`; WAV READY 세린 **63/67** + 태온 **1/85** = **64/152**, 남은 **88**. `HOLD=False`.
5. 이 예시는 **실제 API 전환 및 저장·사용량 장부가 작동했다는 검증**이다. **KEY 4개가 실질적인 Google Project 4개에 각각 속한다는 원격 Project ID 증거, 429가 일일 RPD였다는 증거, 만들어진 64개 전량의 인간 청취 QA PASS 증거는 아니다.** 로그의 `PROJECT_1` 등은 로컬 그룹 라벨이다.

## 2. 절대로 어기지 않을 운영 원칙

1. **모델·Google Project 기준 할당량:** 키 개수와 독립 프로젝트 개수는 별개. Google API 키→실제 Google Project **ID**를 먼저 조사하고, 동일 프로젝트라면 무조건 **동일 그룹**. 특정 모델의 RPM/TPM/RPD, 실제 무료·유료 요금상태를 따로 확인한다. Google의 적용 정책 및 이용약관을 준수할 것.
2. **예산 이중 게이트:** 사용자가 지정한 하루 전체 **로컬 최대 POST 시도 횟수** 및 **모델·프로젝트별 보수적 상한**을 모두 충족하는 경우만 요청한다. 예: 10/21 세린·태온 작업은 로컬 40회 및 그룹별 안전 10회. 이는 그날의 **운영 설정 예시**일 뿐 다른 TTS에 40·10을 자동 적용하면 안 된다. 실패·타임아웃·응답 불명도 **로컬 시도 1회**로 기록하여 초과를 막는다. 서버 실제 차감·과금 수는 다를 수 있다.
3. **PT 기준 날짜 구분:** Gemini 일일 RPD는 제공자 안내에 따른 **미국 태평양 날짜 자정** 리셋(서머타임 PDT/PST 적용); 한국 자정이 아님. Python은 `zoneinfo.ZoneInfo("America/Los_Angeles")` 같은 IANA timezone으로 날짜 계산해야 한다. 날짜 변경 시 **그날의 로컬 카운터·격리만 새 계산**, 전체 이력은 결코 삭제하지 않는다. Google 쿼터 실제 복귀는 별도 확인.
4. **한 대사당 하나의 승인 가능한 WAV:** Stable Dialogue ID + Speaker + 원문 + Voice + 모델/스타일을 정본으로 고정. 대사 ID 하나의 기존 **정상 출력 파일이 있으면 건너뛰고 재생성/덮어쓰기 금지**. 실패·429의 **재시도는 API POST가 추가로 소모되므로 별도 ATTEMPT 기록**, 한 ID에 여러 *시도*가 생길 수 있으나 최종 WAV은 하나만 관리.
5. **429를 성공/실패/차단으로 구별:** 429는 성공 WAV가 아니며 안전한 다른 **독립 프로젝트**가 있는 경우에만 그날 실패 그룹을 격리하고 진행. 같은 프로젝트의 다른 키는 모두 격리. 다른 그룹이 없다면 전체 HOLD 또는 당일 CAP 정지. 현재 코드는 429 본문의 RPM/RPD 상세 진단이 부족해 **같은 태평양 날짜 전체 격리**하는 보수적 정책을 사용한다. 429 자체만으로 일일 한도라고 단정 금지.
6. **불확실한 응답은 자동으로 재시도하지 않는다:** HTTP400/500/네트워크 타임아웃/프로세스 강제종료/파일 생성 중 크래시 등 결과 미확실 시 FAIL/HOLD+LOCK 기록 후 중단. 서버가 요청을 처리했지만 응답을 못 받은 경우 중복/과금 위험 있으므로 복구 도구의 원본 증거/파일/장부 검증과 사용자 승인 후만 재개한다.
7. **승인 분리:** WAV 파일 존재·PCM16/24kHz·SHA PASS는 **기술 QA**이지 인간의 실제 발음·화자성·인물 성격·문장 운율·원문 일치 QA를 대체하지 않는다. 사용자의 실제 음성 PASS와 Codex Unity 연결 PASS를 별도 기록한다.
8. **보존·보안:** 과거 사용자 승인 WAV/샘플 및 .meta/GUID, Unity Catalog·Save, `API.txt`, 장부, 실패 스냅샷을 삭제/덮어쓰기 금지. 키 값은 절대로 문서·GitHub·WAV JSON·예외 traceback·화면 보고에 출력하지 않는다. 슬롯 번호만 기록.

## 3. 범용 배치 설정 계약(신규 구현의 권장 인터페이스, 현재 스크립트와 그대로 호환 보장 아님)

작업 단위는 **BatchID**를 가진 독립 워크스페이스다. 같은 프로젝트를 쓰는 **서로 다른 TTS 배치들**(하렌·세린·태온·내레이션)이 같은 날 나눠 호출하는 경우, 작업별 장부의 합계만으로 실제 프로젝트 총사용량을 알 수 없다. **공유 Project/Model 일일 장부를 합산하거나 공식 Usage에서 외부 사용량을 선확인**해야 한다.

### 설정 항목

| 범주 | 권장 키 또는 데이터 | 설명 |
| --- | --- | --- |
| 기본 | `batch_id, workspace_root, model_id, time_zone=America/Los_Angeles` | 인물·챕터 독립 실행, 같은 저장소 덮어쓰기 금지 |

## 4. 이벤트·파일 정합성(현행 운영에서 재사용할 핵심)

### 부작용 없는 사전 점검

- `check`는 키 *개수·중복*, manifest Stable ID/화자/원문 SHA, 샘플·WAV 파일 검증, HOLD/LOCK 상태, 로컬 API 슬롯·Project Group 및 PT 날짜·모델 확인. **Google POST 요청을 보내지 않는다**.
- 프로젝트 매핑은 **로컬 라벨만으로 확인되었다고 가정하지 않는다**. 서로 다른 실제 프로젝트인지 확인되지 않으면 Failover 꺼두고 한 그룹 공유 한도로 관리.
- 이전 승인 샘플이 존재하면 파일을 해당 캐릭터 폴더에 **복사**하고 파일 해시/모델·Voice 일치 검증으로 제작 완료로 간주하되 **사용 API 카운트 0**. 원본 복사·재사용 여부는 출처를 메타에 명시.

### POST 전후 트랜잭션

1. `(ProjectID, ModelID, PTDate)`에 대한 모든 관련 작업의 사용량을 확인하고 전역·그룹별 최소 잔여를 계산.
2. 미완료 Stable ID를 하나 선택. 기존 WAV + JSON SHA와 원문 일치, 잠금·다른 실행자가 같은 ID를 처리 중이지 않음을 확인.
3. **POST 전 원자적으로 RUNNING.lock 및 `ATTEMPT` 선기록**(UTC 시각·PT날짜·BatchID·DialogueID·실제 text 또는 해시/보호된 본문·Speaker/Voice/Model·KEY 슬롯·Group·요청 식별자; 비밀키 제외). 이 시점부터 로컬 시도 1회로 집계.
4. Google `generateContent` POST 1회. 요청간격 제한. 성공 응답에서 WAV PCM 단일채널 등 검증 후 **임시 파일 → 원자적 rename** 및 SHA·요청 메타 저장. `SUCCESS` 이벤트 append, `USER_LISTENING_PENDING` 설정. 장부와 파일 불일치 시 자동 호출 재개하지 않는다.
5. 429인 경우 `FAIL(HTTP429)` 기록하고 Group을 해당 PT날짜 `PROJECT_QUARANTINE`. 다른 **검증된 독립 Project**에 로컬 예산·실제 quota가 남은 경우에만 같은 미완료 ID에 **새 ATTEMPT**로 다음 POST. 없음/검증미완이면 안전 중단.
6. 그 외 오류(HTTP400, 500, 인증오류, timeout, 응답불명 등)는 `FAIL/UNKNOWN`과 HOLD+RUNNING.lock 보존 후 **자동 호출 종료**. 원본 장부/로그/부분 WAV 삭제 금지.

**개념 의사코드 (직접 실행 가능한 완성 스크립트가 아님):**

```text
for each target in approved_manifest:
    if existing_wav_matches_id_text_voice_sha(target): continue
    while global_PT_attempt_budget_available():
        group = select_group(verified_project_map, project_model_budget,
                             exclude_today_quarantined=true)
        if no eligible group: stop_safely_without_hold_if_no_inflight()
        journal_append(ATTEMPT, target, group, slot)  # before POST
        result = POST_one_tts_request(target, group)
        if result.success:
            save_wav_and_metadata_atomically()
            journal_append(SUCCESS); break
        journal_append(FAIL_or_UNKNOWN)
        if result.http_status == 429 and verified_independent_groups_exist():
            journal_append(PROJECT_QUARANTINE, group, PT_date)
            continue  # new group and a NEW ATTEMPT, never free retry
        create_HOLD_and_LOCK_and_stop()
```

**한도 종료 ≠ 장애:** 모든 독립 그룹 cap이 찼을 때 `[GROUP/KEY CAP]` 표시, `HOLD=False`로 정상 종료. 남은 전역 로컬 예산이 1회여도 다른 그룹 슬롯이 없으면 호출하지 않는다.

## 5. 재시작·복구·날짜 리셋(공통 상태 머신)

| 상태 | 의미 | 다음 동작 |
| --- | --- | --- |
| `PENDING` | 원문 대상 있으나 WAV 없음 | quota/캐스팅/잠금 확인 후 요청 가능 |
| `IN_FLIGHT` | ATTEMPT 선기록, POST 결과 미완료 | 중복 호출 중지, 잠금 및 증거 확인 |
| `SUCCESS_TECH_QA` | WAV+SHA+PCM+메타 일치 | 중복 생성 건너뜀, 사용자 청취 대기 |
| `LISTENING_APPROVED` | 사용자 실제 발음/캐릭터/운율 승인 | 해당 캐릭터 전 챕터 일관성 점검 후 Codex 적용 |
| `PROJECT_QUARANTINED` | 해당 프로젝트 429/그날 사용정지 | **그룹 내 키 전부 제외**, 유효한 다른 그룹만 가능 |
| `CAP_STOP` | 전역/그룹 안전예산 모두 소진 | HOLD 없이 다음 PT날짜 또는 관리자 예산 재검토 |
| `HOLD_LOCKED` | 결과불명·위험한 오류·차단 후 수동 개입 필요 | snapshot/backups/장부 확인→사용자 승인 후만 resume |
| `UNITY_APPLIED` | Codex가 승인 음성 게임 연결·회귀 QA | 브랜치·커밋·검수 보고 |

- **PT 날짜 경계:** 지난 날짜 이벤트는 보존. 새 날짜의 로컬 카운트만 집계하며 **옛 WAV는 유지**, 전날 `PROJECT_QUARANTINE`만 과거 이력화. 단 서버에서 실제 가능한 상태인지 확인 필요.
- **CAP_STOP/HOLD 구분:** `HOLD=False`라면 불필요하게 recovery 스크립트를 실행하지 않는다. 실제 결과불명으로 잠겨 있으면 `HOLD.json` 및 `RUNNING.lock`를 임의 삭제하지 않는다.
- **429 기존 HOLD 수동복구:** 원본 증거 대사/마지막 ATTEMPT/FAIL/키/그룹/중간 WAV/파일 SHA를 교차 검증→`recovery_snapshots` 원본 그대로 백업(해시 포함)→사용자 확인 입력→그때만 잠금 해제. 별도 검증된 프로젝트가 없다면 같은 날짜 무리한 재실행 금지. 이전 429의 정확 RPM/RPD 원인 불명이라면 보수적으로 다음 PT 날짜를 기다리는 정책 가능.
- **로그 설계 개선 과제:** HTTP429 응답에서 마스킹한 `error.status`, `error.message`, `Retry-After`/관련 rate-limit header가 허용되면 저장하도록 개선. **429가 RPM·TPM·RPD 중 무엇인지 무근거로 단정하지 않고**, 향후 유형별 bounded cooldown/backoff와 daily quarantine을 분리할 수 있도록 설계한다. 현재 v2에서는 그 분리 로직이 **구현되었다고 주장하지 않는다**.

## 6. 다른 TTS에서 재사용하는 절차

1. **새 BatchID와 독립 폴더**를 정하고 그 캐릭터의 Story 원문 Manifest를 실제 GitHub 정본으로 만든다(대사 ID·원문·분기·화자·순서·Voice·Style·Source SHA, 중복0). 세린/태온 하드코딩 152 리스트를 그대로 쓰지 않는다.
2. 캐릭터별 공식 Voice 성별·성격을 확인하고 **한국어 샘플 1개 먼저 실제 청취 승인**. 아이템·내레이션도 대사 내용·운율·발음 검수. 이미 승인된 기존 WAV는 원본 복사/보존.
3. Secret `API.txt`는 로컬 파일로만 보관하며 `;`와 줄바꿈 구분 파서를 재사용할 수 있다. 배포 ZIP에는 포함하지 않고, Git 이력에서 제외. 여러 TTS 배치가 **같은 Project/Model quota를 공유한다면 장부 합산/중앙 ledger**가 필요하다. 독립 프로젝트가 확인되지 않았으면 failover를 활성화하지 않는다.
4. 당일 **정확한 Google Project/Model 무료 잔여·Billing 상태**를 확인하여 `daily_request_budget`/프로젝트 상한/간격을 설정. 오늘 세린 배치 `40/10`을 다른 모델의 고정 quota로 복사 금지.
5. **오프라인 selftest**: 원문 전체/ID 중복0, 이전 WAV/JSON SHA 검증, 성공본 skip, POST 카운트 선기록, 429+독립 프로젝트 전환, 같은 프로젝트 전환 금지, 전체 CAP 정상 정지, HOLD+LOCK+snapshot, PT 날짜 DST 변경, API 키 마스킹, 재실행/강제종료 복구 검증.
6. 처음에는 **최대 1~2 POST**로 실제 입력/출력/로그 점검 → 사용자 청취 승인 후 그 배치만 진행. HTTP429면 해당 프로젝트 격리+다른 실제 독립 프로젝트 조건이 충족되는지 확인. `WAV READY`를 `user approved`로 표시하지 않는다.
7. 제작이 완료돼도 **Unity 자동적용하지 않음**. 전 챕터 한 인물 목소리 일관성 점검, 사용자 최종 승인 후 Codex에게만 원본 보존·GUID/Save/Play Mode 회귀 QA 지시.
8. 사용내역/필요 승인을 최신 인계와 Issue에 보고하고 `docs/tts`에 문서·템플릿만 작성. **main 직접 커밋·Push/merge 금지**.
