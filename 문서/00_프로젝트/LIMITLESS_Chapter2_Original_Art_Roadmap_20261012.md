## 1. 사용자 결정 — 담당 경계 확정

Chapter 2의 무료/공용 아트 느낌을 줄이고 **지역 환경 → 몬스터 → 펫 → 마을 NPC → VFX**까지 LIMITLESS의 통일된 오리지널 아트로 단계적으로 바꾼다.

**Chapter 1·2 기존 자산 리뉴얼의 발주·제작·패키지 납품·미술 보완은 리뉴얼 담당이 일원화한다.** 환경만 리뉴얼 담당, 몬스터와 펫은 별도 스프라이트 담당, VFX는 또 다른 팀으로 나누어 병렬 발주하지 않는다. 작업 영역별 전문 기술이 필요하더라도 사용자 지시와 결과 집계의 단일 창구는 리뉴얼 담당이다.

**기존 스프라이트 담당은 Chapter 3 이후 모든 신규 아트를 전담**합니다. Chapter 1·2 기존 자산 리뉴얼에 중복 발주하지 않으며, Chapter 1·2 기존 승인 공식 캐릭터 및 몬스터를 명시적 재제작 승인 없이 교체하지 않습니다.

Codex는 오리지널 이미지를 창작·선택하는 담당이 아니라 기존 게임 현장 조사, 대응표, Import/Animator/Scene 연결, 회귀 QA와 선별 Commit을 맡는다. Codex Push는 사용자에게 맡기고, 사용자 미커밋 변경을 반드시 보호한다.

## 2. 작업 순서 — 지역 환경부터

Chapter 1 기존 리뉴얼 완료분을 자동 재작업하지 않는다. 현재 별도 기술 보완인 `Dungeon_01` B1 봉인문과 `Field_03` Rock B 수정본 적용이 진행 또는 대기 중이다. 이들은 이미 지시한 Codex 후속 범위로 유지하며 신규 Chapter 2 환경 작업과 섞지 않는다.

각 지역은 (1) 현행 Scene/Texture/Renderer 역할 감사 → (2) 대표 분위기·Palette 및 반복 타일 설계 → (3) 개별 사용가능 PNG·Sprite 대조표 → (4) 실제 Scene 기반 Preview → (5) 사용자 미술 승인 → (6) Codex 격리 Import/Runtime → (7) Codex 선별 Commit 및 사용자 Push 순서로 진행한다.

### 단계 B. 몬스터 오리지널화

1차 범위는 Chapter 2의 기존 실제 정의 및 배치에서 감사로 확정한다. 공개 기획상의 대표 5종은 **그을음들개 `soot_hound`, 열풍매 `heatwind_hawk`, 균열도마뱀 `fissure_lizard`, 화열딱정벌레 `ember_beetle`, 불씨망령 `ember_wraith`**이다. 후반 지역의 **흑요석 갑충 `obsidian_beetle`, 작열 감시자 `scorching_watcher`, 열맥 거신 보스** 등의 실제 게임 적용 범위도 최신 MonsterDefinition/스토리/`CURRENT_STATUS` 기준으로 검사한다.

**주의:** 기존 5종의 공식 수정 시트가 이미 사용자 제공본으로 프로젝트에 등록된 기록이 있으므로, 이를 '무료 에셋'이라 단정하거나 무조건 교체하지 않는다. 먼저 출처/승인/화면 이질감을 확인하고 **필요한 자산만 교체 제안**한다. 기존 보스/엘리트 및 공식 몬스터 승인 시트는 사용자 명시적 교체 승인 없이 덮어쓰지 않는다.

몬스터별 필드 Idle/이동, 전투 Idle/공격/피격/KO 또는 현재 실제 사용 프레임 구조를 조사한다. 기존 공격 대상 판정·프레임 이벤트·실루엣·Sorting·타격 효과·몬스터 stable ID/스탯/상태이상을 유지한다. 스프라이트 규격은 개체별 실제 Importer/Runtime에 맞춰 결정하며 일괄 128px 등 임의 통일하지 않는다.

### 단계 C. 사수 야수 동료(펫) 오리지널화

기본 **Wolf/Bear/Fox** 3종을 포함하여 현재 분양/사용 가능한 동물형 몬스터의 펫 표현을 감사한다. Chapter 2에서는 그을음들개·열풍매·균열도마뱀·화열딱정벌레 등 실제 분양 규칙이 있는 종을 확인한다. 불씨망령은 분양 대상이 아니다.

사수 BeastCompanion 시스템의 기존 장착·영구 해금·종별 패시브·`동료의 습격` 연출, 세린 사수 동료의 펫 표현을 유지한다. 펫에게 별도 파티 슬롯/독립 턴/HP를 추가하지 않는다. 기존 펫/몬스터 시트 재사용 방식이 적절한 경우 이중 제작 대신 동일 정본의 필드·전투 노출만 개선한다.

### 단계 D. 마을 NPC 오리지널화

아르벨 NPC부터 시작하고, 필요하면 Chapter 1 시작 마을의 배경 주민도 후속으로 감사한다. 우선 **레온, 상점·치유·Party Guide·펫 분양/관리·서쪽 정보 주민·Portal 관리인**, 이어 반복 주민·배경 주민 순서로 조사한다. 기존 공식 주요 인물/초상화, 현재 주민/퀘스트 NPC의 ID, 대화, 상점 가격, 분양/관리 기능과 상호작용 위치는 변경하지 않는다.

먼저 공용 임시 NPC와 독자적인 공식 캐릭터를 분류한다. 새 NPC 디자인은 역할·나이대·실루엣·장소가 구분되고 접근성에 맞게 이름표와 상호작용 영역의 대비를 확보한다. 승인된 레온/세린/하렌 등 주요 인물의 공식 외형을 대체하지 않는다.

### 단계 E. VFX 오리지널화

최종 아트 Palette/대비가 확정된 뒤 **공용 피격·방어/회복 → 독·화상·감전·침묵·과열 등 상태 → 5직업 스킬 → 몬스터/보스 전용 → 환경 효과** 순서로 처리한다. Chapter 3의 한기·동상·동결괴사는 현행 코드 미구현 상태이므로 향후 확정 계약이 나오기 전 런타임 추가를 지시하지 않는다.

광과민·시각 피로를 고려해 지나친 점멸, 화면 전체 덮기, 색상만으로 상태 구분하는 연출을 피한다. 스킬의 발생/피격 타이밍과 피해 판정은 변하지 않는다. 기존 승인 VFX와 타사 자료는 원본/라이선스 보존.

## 3. 작업 단위와 파일 납품 표준

- **지역별/몬스터 종별/펫군별/NPC 역할군별/VFX 계열별**로 제작·검수·승인 단위를 나눈다.
- 리뉴얼 담당의 기본 납품은 실사용 투명 PNG(필요하면 시트), 실제 프레임 배열표, `Manifest.json`(source/role/target 대응·해시·크기·PPU/Pivot 제안), `README.md`, Contact Sheet, 기존/후보 Preview, Alpha/Seam/접지 QA, 출처·상업적 권리 선언, Codex 인계서, ZIP이다.
- Preview만 완성된 것을 실사용 자산 완료로 보고하지 않는다.
- 합성 Preview는 합성이라고, 실제 Unity RenderTexture는 실제 화면이라고 구분한다.
- 사용자 미술 승인 전 현행 Unity 자산 영구 교체 금지. 승인 후에도 Codex Runtime PASS 전에는 통합 완료로 표시하지 않는다.
- 기존 Scene/Save/meta/GUID/퀘스트/전투 수치·TTS/BGM·사용자 수정 원본을 보호한다.
- 최종 사용자가 직접 `git push`를 실행하므로 제작 담당 및 Codex 모두 임의 Push하지 않는다.

## 4. 인계/문서화 기준

리뉴얼 담당은 최신 진행 표에 각 대상 `NOT_STARTED / ASSET_AUDIT / ART_IN_PROGRESS / USER_ART_REVIEW_PENDING / USER_ART_APPROVED / CODEX_INTEGRATION / RUNTIME_PARTIAL / COMPLETE` 등을 기록한다. 완료 씬, 수정 필요 기술 보류, 최종 승인 버전과 미승인 후보를 분리한다.

제작 담당에게 Codex 현장 검수 자료가 필요하면 **로컬 파일을 사용자에게 반복 업로드하라고 하지 말고** Codex용 조사 프롬프트를 제출한다.

장시간 세션이 꽉 차기 전에 사용자에게 사전 보고하고 `문서/00_프로젝트/팀운영/인계/WORLD_ART_RENEWAL_LATEST.md`를 갱신할 수 있게 한다. 대화 세션 간 자동 소통을 가정하지 않는다.

## 5. 즉시 진행할 첫 작업

1. 현재 Codex의 기존 B1 봉인문/Field03 Rock B 보완이 완료되었는지 `CURRENT_STATUS`에서 확인한다. **이 업무를 신규 Chapter 2 리뉴얼과 중복 지시하지 않는다.**
2. Chapter 2 전체 환경(Arbel 및 Field04~11)의 현행 아트/기능 정본을 목록화하고, **첫 제작물은 Field_04_WesternBorder 오리지널 환경 아트 v1**로 납품한다.
3. 다음 지역의 제작은 첫 지역의 미술 스타일·규격이 승인된 뒤 같은 기준으로 이어 간다. 다른 지역의 제작 기준 조사·일괄 자산 목록화는 병행 가능.
4. 환경 전체가 승인·적용된 다음 기존 공식 몬스터와 임시 무료/공용 몬스터를 구분해 후속 오리지널화 범위를 확정한다.

**책임 분리 결론:** 리뉴얼 담당은 Chapter 1·2의 기존 아트 교체만, 기존 스프라이트 담당은 Chapter 3 이후 신규 아트 전체만 담당한다. 기획 담당은 계약·우선순위를, Codex는 Unity 적용과 기술 QA만 맡는다.
