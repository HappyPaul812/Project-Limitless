# LIMITLESS TTS — 캐스팅 성별 역전·음색 불일치 사고 보고서 및 3인 재캐스팅

**작성일:** 2026-10-20
**작성/소관:** LIMITLESS TTS 담당
**문서 성격:** Postmortem / 원인 분석 / 재발 방지 / 최신 작업 인계
**상태:** 사고 정리 및 캐스팅 후보 3명 선정. 사용자 공식 데모 긍정 평가. 실제 LIMITLESS 한국어 WAV 생성 및 최종 캐스팅 승인 대기.
**적용 범위:** 하렌·세린·태온만. 폴·미엘·레온·내레이터 등은 기존 유지.

> **결론:** 근본적인 업무상 문제는 공식 Voice ID의 성별·캐릭터 성격 일치를 선행 확인하지 않고, 기존 음성의 일시적 청취 합격을 해당 Voice ID의 장기 음색 안정성으로 오해한 것이다. Google이 실제 오류를 수정했는지 여부는 확인되지 않았다. 기존 290개 스토리 음성을 전체 폐기하는 대신 하렌·세린·태온 세 캐릭터만 처음부터 같은 새 목소리로 제작하는 방향으로 범위를 확정했다.

## 1. 무엇이 잘못되었나

기존 Voice Registry 및 제작 스크립트에서
- **세린:** 약 25세 여성 / 청각의 길 / 사수 / 기존 Schedar. Google 공식 Voice 목록에서 **Male**.
- **태온:** 남성 / 지적의 길 / 수호자 / 기존 Gacrux. Google 공식 Voice 목록에서 **Female**.
- 폴 Achird=Male, 미엘 Sulafat=Female, 레온 Orus=Male 등 다른 기존 캐릭터는 이번 사고의 직접 변경 대상이 아니다.

Google의 공식 분류는 Voice의 **기본 성별 메타**이며, 모든 실제 결과의 청취 음색을 보장하는 계약은 아니다. 과거 생성된 세린 음성 중 바울 대표가 여성처럼 들린다고 승인한 WAV가 실제로 있으며 일부는 Unity에 적용되었다. 최근 동일 Schedar로 만들어진 세린 음성은 반복적으로 남성처럼 들린다고 사용자가 판정했다. 태온 Gacrux도 최근 여성으로 들린 사례가 있다.

**문제는 단발 품질 불합격을 넘어 한 인물의 챕터별 목소리가 달라질 수 있다는 게임 전체의 연속성 위험**이다. 새 대사만 다른 성우로 제작하면 이야기가 진행될수록 캐릭터 정체성이 훼손된다.

### 무료 사용량·금액 기록의 제한

최초 POST HTTP400 1회와 진단 POST 성공1회는 명시적으로 기록되어 있다. 후속 시험과 이전 날짜의 호출까지 포함한 **실제 Google 프로젝트별/모델별 합계 차감 횟수는 여기서 확정하지 않는다**. 사용자 “18회 버리더라도”는 의향으로, **18회 실제 소진 증거가 아니다**. 오프라인 DSP WAV16개는 API 호출16회가 아니다. 본 사고 보고 작업의 새 Google TTS 생성 호출은 0회다.

## 3. 사고 원인의 증거 수준

### 확정된 사실
1. 제공자 공식 성별 분류 Schedar=Male, Gacrux=Female. 해당 캐릭터 의도 성별과 서로 반대.
2. 사용자 직접 청취: 최근 세린 Schedar 다수 남성으로 들림, 태온 Gacrux 신규 후보1 여성으로 들림.
3. 이전에 승인된 WAV와 최근 불합격 WAV 모두 실제 존재한다. 과거 승인·후속 불합격의 공존을 임의로 삭제하지 않는다.
4. 오프라인 DSP/PSOLA 16개 전량 청취 불합격.
5. 공식 캐스팅 데모 세 사람은 사용자 1차 긍정 반응만 확인됐다.

### 가능한 설명이지만 미확정
- 최초 합격 음성이 서비스/모델의 일시적 음색 이탈이었다.
- 이후 Google의 음색 동작 또는 서버 측 배포가 변경되었다.
- 제작 당시 Style/SDK/모델 옵션이 음색을 바꾸었을 수 있다.

**Google이 버그를 수정한 날짜나 내부 변경 원인은 확인하지 못했다.** 당시 성공 요청의 정확한 wire payload/서버 버전/원시 응답 정보가 없으므로 인과관계 단정 금지.

### 별도의 HTTP400 기술 사건
- 10/20 최초 POST의 상세 에러본문이 스크립트에 저장되지 않은 로깅 결함이 있었다.
- 다른 모델 GET에서 잘못된 키로 인증 거절된 것은 **그 GET 당시 입력한 키에 한한 확정 사실**이며 최초 POST 원인으로 소급할 수 없다.
- 유효 키로 모델 GET 및 단일 TTS 생성은 이후 성공했으나 이는 음색 품질과 무관하다.

## 6. 담당 책임과 교훈

**TTS 담당의 절차상 책임:** Voice ID를 확정하기 전에 캐릭터의 공식 성별/나이감/톤과 Google의 성별/음색 메타를 교차 검증하지 않았고, 일관성 있는 샘플 청취 승인 절차가 없었다. 사용자가 실제로 승인한 *들리는 목소리* 대신 **Voice ID를 고정 정본**으로 해석했으며 실패 뒤 무리한 재생성·파형 보정 작업으로 시간을 소모했다. 사용자에게 책임을 전가하지 않는다.

**코드/로그 결함:** 최초 POST HTTP400 error.message 저장 누락. TTS 실패·쿼터·불확실한 응답을 즉시 HOLD하고 원문 오류를 마스킹 저장해야 한다.

**품질 정책:** 샘플레이트/PCM16/파일 SHA/Unity Runtime PASS 등은 **기계적 검증**이고, 캐릭터 성별 지각·발화 내용·감정·일관성은 **바울 대표 실제 청취 검수**가 별도로 PASS여야 한다.

**기술 접근 제한:** 피치/포먼트/EQ는 성별·화자 고유 음색을 안정적으로 바꾸는 검증된 Voice Conversion이 아니다. 단순 재조절 반복 금지. 과거 synthetic WAV로 Google Voice Replication을 곧바로 사용할 수 있다는 주장도 요건 검증 없이 하지 않는다.

## 7. 재발 방지 및 실행 게이트

1. **캐스팅 기획:** 캐릭터 성별·성격·말투·관계 정본 확인 → Google Voice 공식 Gender/특성 확인 → 다른 인물과 중복·혼동 방지.
2. **1개 한국어 실대사 오디션:** 하렌 Alnilam1, 세린 Erinome1, 태온 Algieba1. **Google Project+Model의 실제 무료 quota/과금 상태를 먼저 검증**하고 비밀키는 사용자 로컬에서 마스킹 입력. 호출은 본인이 승인한 만큼만 수행, 무단 반복0.
3. **청취 승인:** 한국어 발음·캐릭터 성별/성숙도·형제 반말/관찰 대사·폴/미엘/레온 구분·조용한 대사와 감정 대사 간 일관성 평가. 실패시 차선 후보만 제한적 오디션.
4. **제작:** 한 인물 전체 확정 ID를 동일 Voice/기본 Style 규칙으로 일관되게 제작. Dialogue ID/실제 원문/StoryOrder/Path 분기 보존. 성공 WAV 불필요 재생성 금지. 모델·Voice·Style·실제 request/응답메타·생성일·SHA·청취 상태 기록.
5. **적용 전제:** 하렌은 3개 전체 승인, 세린 67개, 태온 85개는 각각 **처음 등장하는 챕터부터 전 구간**을 준비한 후 사용자 승인 → Codex가 검증된 작업브랜치에서 Unity 적용. **한 인물 구/신 음색 혼합 배포 금지**.
6. **보호 및 검증:** 기존 WAV/Clip/Meta/GUID/Save/Settings/HOLD·dirty 변경 보존, 백업 및 sha 목록 작성. Next/Voice Mixer/Mute/Quest/SaveContinue 런타임 회귀. 이력 보존을 위해 과거 제작 Meta를 임의로 재기록하지 않음.
7. **승인·Git:** TTS 담당 문서·Python/QA, Codex Unity 구현·검증, 바울 대표 최종 캐스팅/적용/main 통합 승인. main 직접 커밋/Push/강제 덮어쓰기 금지. 모든 보고에 브랜치·커밋 SHA·사용자 승인 필요 여부 포함.
