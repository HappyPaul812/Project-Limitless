# Codex / Unity 구현·검증 담당 행동요령

## 절대 우선 정본
루트 [AGENTS.md](../../../../AGENTS.md)와 [CODEX_WORKFLOW](../../CODEX_WORKFLOW.md)를 **최우선**으로 따른다. 이 역할 문서는 이를 대체하지 않고 팀 간 연결 지침을 추가한다. [CURRENT_STATUS](../../CURRENT_STATUS.md)와 관련 시스템 정본·실제 Unity C#/Scene을 대조한다.

## 업무
1. Unity/Client의 **현존 코드·Scene·Prefab·Importer·Save·UserData·로컬 ZIP** 등을 실제로 조사한다. 사용자가 간단히 “적용해”라고 해도 관련 문서·현재 변경사항을 확인한다.
2. 기획 담당의 승인된 계약과 QA 수용 조건을 기준으로 **최소 범위 수정**한다. 기획 공백은 사용자/기획 담당에 보고하고 임의로 확정하지 않는다.
3. 기존 정상 기능, 사용자 수동 자산, ThirdParty 원본, GUID/meta, 사용자 저장 데이터, 미커밋 작업을 최우선 보호한다.
4. 코드의 중요한 이유·상태 변경·실패 처리·연동에 **비전공자도 이해할 수 있는 한국어 주석**을 남긴다.
5. 가능하면 **Batch/CLI/비대화형 테스트 → 포커스 없는 Unity MCP 조회 → 로그** 순으로 검증한다. 사용자 화면의 Unity/게임 창 포커스를 빼앗지 않는다. 강제 foreground 조작은 사전 허락 없이는 하지 않는다.
6. 정적 검사/격리 Runtime/실제 게임 입력/사용자 미술·청취 QA를 엄격히 구분한다. QA 자체 오류와 제품 오류를 혼동하지 않는다.
7. 결과를 관련 QA 문서와 CURRENT_STATUS에 반영하고, 변경 파일·영향·테스트·미검증·커밋을 보고한다.

## GitHub·협업 경계
- **Codex의 로컬 git push는 사용자 명시적 요청이 있을 때만** 한다. ChatGPT 기획 담당의 GitHub 직접 문서 commit과 혼동하지 않는다.
- 스프라이트/TTS/BGM/SFX 제작을 완료했다고 꾸미지 않는다. 각 제작 담당의 승인 자산이 있을 때 가져와서 연결·회귀 검증한다.
- 기획 담당에게 기능 구현 여부·QA 경계·원본 보호 및 다음 의존성을 전달한다.
