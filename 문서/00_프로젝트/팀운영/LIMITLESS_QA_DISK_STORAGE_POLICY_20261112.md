# LIMITLESS — Unity/Codex QA 디스크 자원 관리 및 정리 운영 규칙

- **확정일:** 2026-11-12
- **확정 주체:** 바울 대표 (기획 담당 기록)
- **적용:** Codex 구현·QA, 모든 아트/오디오 검증, 야간 EOD, 후임 세션
- **상태:** 운영 원칙 확정 / 게임 파일 수정·기존 worktree 삭제·원격 Push 승인과는 별개

## 1. 확정 운영 원칙

1. **격리 Unity 프로젝트 무분별한 신규 복제 금지.** 기존 검증 환경을 먼저 탐색하여 재사용하고, 기능·패키지 충돌 등의 구체적 필요가 있을 때만 새 격리본을 만든다. 새 격리본 필요성, 예상 디스크 증가량, 정리 시점을 작업 계획에 포함한다.
2. **작업 시작 전·종료 후 실제 F: 여유 공간 측정.** 합산 폴더 크기가 아니라 실제 디스크 여유 공간과 하드링크/중복을 구분하여 보고한다. 디스크 여유가 부족하거나 예상보다 급격히 줄면 신규 복제·대규모 Import/QA를 중단하고 원인과 필요한 범위를 보고한다. 확인되지 않은 수치로 안전을 보장하지 않는다.
3. **검증 완료와 임시 환경 정리를 동일한 완료 기준으로 관리.** 테스트에 사용한 재생성 가능한 캐시, 안전이 검증된 임시 디렉터리·로그는 가능한 범위에서 그 회차 안에 정리한다. 삭제 대상·실제 회수 용량을 보고하고, 미완료·불명확한 파일은 HOLD한다. 별도의 백그라운드 자동 정리 프로그램이 구축된 것은 아니다.
4. **검증 중복 최소화.** 기존 PASS는 그대로 보존하고 변경된 영역만 Delta QA 한다. 동일 검사·Unity Import 전수 재실행과 증거 자료의 다중 복제를 피한다.
5. **새 작업이나 정리 지시 시 Codex 사용량을 고려.** 이용 가능한 주간/5시간 한도와 실제 작업 우선순위를 먼저 검토하고, 효율이 낮은 용량 절감 반복 작업은 중단한다. AI 한도와 별개로 Windows 디스크를 자동 모니터링할 수 있다고 주장하지 않는다.

## 2. 절대 보호 항목

- 원본 Unity(승인 Scenes/Assets/Packages/ProjectSettings/GUID/meta), 개발 브랜치, **미Push 커밋**, 미커밋·미추적 사용자 작업, Save/UserData/UserSettings.
- 스토리·기획 문서, 승인 아트·TTS·BGM·SFX, 상업적 라이선스·원본 출처, 복원에 필요한 증거.
- **Discord AI 협업 관련 모든 작업/설정/봇/MCP/스크립트/인증자료 및 보호 경로**: 사용자 명시 지시로 삭제 금지. 설정 변경이나 실행도 별도 요청 전에는 하지 않는다.
- Issue #85 Clean Release/PSD Import/GUID 조사, 필수 복구 자료와 로컬 원본 main. Unity Editor **6000.6.5f1** 고정.
- Git worktree는 활성 연결, 미Push ref, 미커밋·미추적·고유 파일 및 복구 가능성을 확인해야 하며 **`git worktree remove --force` / `git clean -fdx` / `git reset --hard` 사용 금지**.

## 3. 백업 및 삭제 판정

- 논리적 크기와 실제 고유 데이터/NTFS File ID/하드링크를 구별한다. 동일한 내용의 파일이라도 사용·참조·권한·저장 경로가 다르면 무단 삭제하지 않는다.
- 삭제 전 파일별 고유 데이터, Git ref/미커밋, 사용자 저장, Discord 연관 여부, 다른 worktree 참조를 확인한다.
- 외장하드 백업은 **Git bundle·로컬 브랜치·인덱스·미커밋·Save/원본·복원 절차** 등 실제 복원 가능성 검증이 필요하다. '최소 백업 예상치'는 완전 백업 성공을 의미하지 않는다.
- 안전 검증 가능한 재생성 캐시는 정리할 수 있지만 불명확한 프로젝트·복구 자료의 대량 삭제는 바울 대표에게 별도 승인 요청. 디스크 정리만을 위해 대형 Unity 복제나 추가 전체 QA는 수행하지 않는다.

## 4. 2026-11-12 디스크 정리 관측 결과 (실측이 아닌 Codex 보고 접수)

- 초기 고유 데이터 약 **288.215 GB**, 중간 단계 재생성 캐시 **129개/12.922 GB**, 이후 **291개/36.146 GB**, QA worktree **4개/2.179 GB**, 추가 캐시 **42개/6.402 GB** 순차 정리 보고. **서로 다른 단계의 보고 수치를 중복 합산하지 않는다.**
- 가장 최근 보고 F: 실제 여유 공간 **319.848 → 326.250 GB** (추가 **6.402 GB** 확보). 남은 디스크 파일 총량이나 Unity 프로젝트 실질 최소 필요 용량은 이 수치만으로 확정할 수 없다.
- 이전 감사에서 현재 남은 고유 데이터 약 **252.069 GB** 보고됐으나 이후 추가 삭제가 있었으므로 현재 값으로 재사용하지 않는다.
- 내부 복원 후보 백업 **14.581 GB** 검증 보고가 있었지만, 별도 접근 불가 항목/외장 디스크 완전 백업 보증과는 구별한다.
- 원본/Save/Discord/사용자 작업 보존, **원격 Push/Merge 미실행**, Issue #85 Import/Compile HOLD 지속.

## 5. 2026-11-12 사용량 상황과 작업 중단 결정

- 사용자 화면 기준 **코덱스 5시간 한도 75% 남음 / 주간 한도 13% 남음 / 추가 크레딧 0**. 이는 해당 캡처 시점 값이며 실시간 조회가 아님.
- **결정: 오늘 추가 디스크 정리·코덱스 호출 중단.** F: 여유 공간이 즉시 부족한 상황은 아니고, 주간 한도가 적으므로 더 많은 QA 작업 폴더를 없애려고 호출을 반복하지 않는다.
- 재개 시 실제 남은 공간과 사용량을 먼저 확인하고, 기존 감사·분류표를 재사용한다. 우선순위는 게임 개발과 필수 검증이며, 원격 Push 및 Issue #85 기술 복구는 별도 지시/승인 대기.
- 기획 담당은 지시·운영 문서화와 결과 검토를 책임지며, 사용자 PC의 디스크를 지속 관찰하거나 자동으로 정리·복구할 능력이 있다고 약속하지 않는다.

## 6. 담당 완료 보고 기준

- 신규 격리 프로젝트 수, 재사용한 환경, 실제 늘어난 고유 디스크 공간, 재생성 가능 캐시 정리, **작업 전/후 F: 여유 공간**, 남겨둔 대용량 자료와 근거를 간결히 보고한다.
- Game/Save/Discord/승인 자산/Git ref 등 불변과 검사 범위(실제 PASS / NOT_RUN / HOLD)를 명시한다.
- 문서화는 담당 브랜치 + 커밋 + 필요 시 Issue 링크. **main 직접 커밋·무승인 Push 금지**.
