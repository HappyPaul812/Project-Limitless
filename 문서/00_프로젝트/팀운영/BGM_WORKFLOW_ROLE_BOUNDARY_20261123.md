## 2. 제작 요청 흐름

1. **기획:** 어디에 쓰는 음악인지, 왜 필요한지, 기존 승인곡과 역할이 어떻게 다른지, 금지할 게임 연출과 우선순위만 명시. `[LIMITLESS / BGM 담당 / Issue #...]` 형식으로 담당 세션에 전달하는 **업무 지시문** 제공.
2. **BGM:** 담당 스스로 기존 BGM, 기획 정본/기존 이슈/상업 이용 가능성, 필요 시 리퍼런스 곡의 테마를 확인. **Gemini 생성 프롬프트 작성과 실제 생성 워크플로는 BGM 담당의 고유 책임**. 필요한 플랫폼 접근/직접 실행 권한이 없으면 대표에게 BGM 담당 세션에서 필요한 조작만 정확히 요청(기획 담당이 대신 프롬프트 공급하지 않음). 사용자 승인 없는 새 비용·외부 호출 금지.
3. **BGM 납품:** 원본 경로·파일/버전·길이·규격·SHA256·무료/유료·상용 권리 근거, 기존곡 중복 여부, 실제 청취/QA/루프 승인 상태를 구분한 1차 파일럿 보고. 담당 브랜치 `docs/bgm` 커밋, `BGM_LATEST.md`, 해당 Issue 댓글/실제 SHA 보고.
4. **기획/대표:** BGM 기술 결과 접수 및 대표 청취 승인. 재생성은 불승인 이유가 명확할 때에만 해당 BGM 담당에게 최소 수정 요청.
5. **Codex:** 최종 승인 파일만 따로 Unity 연결. 기존 `main`·Save/UserData·TTS/Mixer/승인 Unity `6000.6.5f1`/Issue #85 HOLD 보호. 병합/Push는 대표 별도 지시.
