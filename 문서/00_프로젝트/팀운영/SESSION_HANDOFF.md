# 세션 한도 사전 경고와 후임 세팅 절차

이 문서는 모든 담당의 세션 연속성을 위한 규칙이다. 실제 대화 용량의 **정확한 남은 수치나 종료 시각은 확인하지 못할 수 있으므로**, 컨텍스트가 길어졌거나 앞선 결정을 재확인해야 하는 징후가 보일 때 선제적으로 인계한다.

## 인계를 시작하는 신호

- 대화가 장기화되어 앞선 지시, 자산 버전, 여러 작업의 완료·미완 구분이 복잡해졌을 때.
- 같은 내용을 재확인하는 횟수가 늘어나거나 일관성을 지키기 어려울 위험이 있을 때.
- 중요한 단계가 끝났고 다음 단계 전에 안전하게 담당을 교체할 수 있을 때.
- 사용자가 명시적으로 “퇴사”, “후임”, “세션 교체”, “인계”를 요청했을 때.

## 세션 종료 전 필수 행동

1. **사용자에게 먼저 보고**: “현재 [담당] 세션은 대화 맥락이 길어져 후임 인계를 준비하겠습니다.” 등으로 이유와 예정 범위를 짧게 전달한다. 정확한 남은 용량을 단정하지 않는다.
2. Github 현재 main과 관련 정본·QA를 다시 확인한다. 확인하지 못한 현장·로컬 상황은 구분한다.
3. 인계 파일 **문서/00_프로젝트/팀운영/인계/[ROLE]_LATEST.md**를 작성·갱신한다. 각 역할의 ROLE 이름은 PLANNING, CODEX, TTS, SPRITE_ART, WORLD_ART_RENEWAL, BGM, SFX, DEV_VIDEO 중 하나다.
4. 아래 구조를 채워 **사실, 결정, 남은 일, 승인, 리스크**를 기록한다. 승인되지 않은 계획을 승인으로 둔갑시키지 않는다.
5. GitHub 쓰기 성공 및 변경 커밋을 확인하고 링크를 보고한다. 쓰기 불가 시 복붙용 인계문을 제공하고 저장 실패를 분명히 말한다.
6. 새 세션 시작 문구를 함께 제공한다. **사용자가 새 대화창을 여는 단계는 사용자가 수행**한다.

## 인계 파일 필수 항목

- **담당/작성일/기준 저장소**: 역할, 확인한 브랜치·커밋, 관련 정본 문서.
- **사용자가 확정한 정책**: 주요 결정과 금지 사항(출처/날짜).
- **완료 및 증거**: 최신 완료 범위, 결과/파일/검증 근거, 적용·push 여부.
- **진행 중**: 현재 작업 단계, 중단 가능한 지점, 기존 자산 보호 필요사항.
- **미결·미검증·블로커**: 사용자 결정 필요 사항과 작업 접근 제약.
- **다음 담당의 1~3개 우선 작업**: 순서와 의존관계.
- **다른 담당 인계**: 어느 역할에게 무엇을 전달할지.
- **후임 첫 답변**: 확인한 자료와 제안할 다음 행동.
- **시작 명령**: “너는 [역할] 담당이다. 깃허브에서 공부하고 와. 특히 문서/00_프로젝트/팀운영/인계/[ROLE]_LATEST.md를 확인해.”

## 중요 제한

- 신설 역할은 실제로 해당 세션이 활동하기 전까지 **인계 파일이 없어도 정상**이다. 빈 내용을 '진행 완료'인 것처럼 만들지 않는다.
- 후임 세션은 인계 파일만 맹신하지 말고 반드시 CURRENT_STATUS와 최신 GitHub 문서를 대조한다.
- 파일이 있어도 실시간 세션 간 자동 통신을 보장하지 않는다.
