## 신입 자동 온보딩 최신 지침 (2026-10-13)

**공통 호칭:** LIMITLESS 프로젝트 내 직접 호칭은 **“바울 대표”**로 고정하고 존댓말로 보고한다. [공통 규칙](COMMON_RULES.md) 참조.


이미 LIMITLESS 담당 역할이 확정된 대화에서는 **“공부하고 와”**만으로 [신입 자동 온보딩 규약](NEW_HIRE_ONBOARDING_20261013.md)을 실행합니다. 완전히 새로운 대화에서는 **“너는 LIMITLESS [담당]이다. GitHub 공부하고 와.”** 한 줄로 역할을 처음 지정합니다. 최신 main·docs/planning·자기 담당 브랜치와 역할 정본·인계·QA를 조회하고, 교육 완료 보고까지 스스로 수행합니다. 교육만으로 게임 변경·Git Push·유료 호출은 허가되지 않습니다.

## 한 줄 호출 규약

사용자가 **“너는 ○○ 담당이다. 깃허브에서 공부하고 와.”** 라고 하면, 해당 담당은 아래 절차를 실행한다. 사용자가 파일을 별도 첨부하거나 긴 설명을 다시 하지 않아도 된다.

1. GitHub 저장소 HappyPaul812/Project-Limitless의 기본 브랜치 main 및 이 문서를 열고, 갱신된 날짜·정본 상태를 확인한다.
2. [공통 규칙](COMMON_RULES.md)을 모두 읽는다. Codex라면 루트의 [AGENTS.md](../../../AGENTS.md)도 우선 확인한다.
3. 아래 역할표에서 **자신의 역할 파일**을 열고 해당 역할의 핵심 정본과 최신 QA·구현 기록을 읽는다.
4. [PROJECT_CONTEXT](../PROJECT_CONTEXT.md), [CURRENT_STATUS](../CURRENT_STATUS.md)의 **최신 기록**과 해당 작업 분야의 세부 문서를 대조한다. CURRENT_STATUS는 최근 항목이 위쪽에 있고 과거 이력이 남아 있으므로 날짜·최종 후속 기록까지 확인한다.
5. [인계 절차](SESSION_HANDOFF.md)의 해당 역할 인계 파일이 있으면 확인한다. 없으면 없다고 하고 최신 정본을 기준으로 시작한다.
6. 읽은 문서와 실제 확인한 범위를 짧게 보고한다: **역할 / 확인한 정본 / 현재 완료·미완·검증 구분 / 우선할 다음 작업 / 필요한 결정**. 바로 실행할 작업이 명확하면 계획·작업 범위를 제시한다.
7. 문서와 코드, 로컬 납품물이 서로 다르면 조용히 덮어쓰지 않고 충돌을 보고한다.
