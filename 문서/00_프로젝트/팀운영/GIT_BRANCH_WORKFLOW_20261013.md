# LIMITLESS Git 협업 브랜치 규칙 — 2026-10-13

사용자 요청에 따라 여러 AI 담당의 동시 GitHub 작업이 main에서 충돌하지 않도록 합니다.

1. **main**은 사용자 승인 후 최종 통합하는 브랜치입니다. ChatGPT 담당자는 main에 직접 커밋하지 않습니다.
2. 기획 담당은 `docs/planning` 또는 `docs/planning-날짜-주제`, Chapter1·2 리뉴얼은 `docs/art-renewal-주제`, Chapter3 이후 신규 아트는 `docs/art-new-주제`, 음성은 `docs/tts-주제`를 사용합니다.
3. Codex 구현/QA는 별도 worktree와 `codex/주제-날짜` 브랜치를 이용합니다. 원본 main 작업 트리와 사용자 미커밋 자료는 보호합니다.
4. GitHub 파일 수정 도구는 항상 작업 브랜치 인자를 명시합니다. 기본 브랜치로 자동 작성하는 요청은 하지 않습니다.
5. 담당자는 브랜치/커밋 SHA/검수 결과를 보고합니다. 문서 브랜치의 변경을 main에 적용됐다고 표현하지 않습니다.
6. 사용자 승인 후 최신 원격 main과의 차이를 검토하고 안전하게 합병합니다. 최종 main Push/합병 시점은 사용자가 결정합니다. 강제 Push로 충돌을 해결하지 않습니다.
7. 여러 담당자가 같은 파일을 동시에 변경하려면 기획 담당과 사전 조율합니다. 다른 담당 브랜치에서 직접 덮어쓰지 않습니다.

## 2026-10-13 Push 충돌 복구 안내

Codex의 통합 worktree에서 시도한 `HEAD:main` Push가 `fetch first`로 거절됐습니다. 이는 통합 커밋 준비 후 기획 문서가 원격 main에 새로 올라간 것이 원인입니다. 기존 통합 결과는 보존된 상태로 간주하되 실제 로컬 커밋/해시 검증이 필요합니다.

Codex는 현재 원격 main을 안전하게 fetch하고 독립된 통합 worktree에 로컬 기존 구현/검수 커밋과 최신 원격 문서를 모두 보존해 새 통합 커밋을 준비합니다. 원본 사용자 수정이나 저장 데이터를 되돌리지 않고, 새 SHA 및 사용자 직접 실행 명령을 보고합니다. 동일한 실패 Push 명령을 재실행하는 것은 해결이 아닙니다.

이 문서는 `docs/planning` 작업 브랜치에 먼저 기록됩니다. main 합병은 Codex 통합 Push 이후 사용자 승인 시점까지 보류합니다.
