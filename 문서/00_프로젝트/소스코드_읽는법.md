# Project-Limitless 소스코드 읽는 법

## 이 문서의 목적

이 문서는 프로그래밍이나 Unity를 처음 접하는 사람이 Project-Limitless의 C# 코드를 읽을 때 필요한 기본 개념을 설명합니다. 처음부터 모든 문법을 외우기보다, 각 Script가 어떤 GameObject에 붙고 어떤 역할을 하는지부터 살펴보면 흐름을 이해하기 쉽습니다.

## Unity C# Script란 무엇인가

Unity C# Script는 게임 오브젝트의 동작을 C# 언어로 작성한 파일입니다. 예를 들어 플레이어의 입력을 읽어 움직이거나, 카메라가 플레이어를 따라가게 하거나, NPC의 대사를 화면에 표시합니다.

`MonoBehaviour`를 상속한 클래스는 대개 Unity의 GameObject에 Component로 붙여 사용합니다. `Editor` 폴더의 Script처럼 게임 실행 기능이 아니라 개발 도구를 만드는 예외도 있습니다.

## GameObject와 Component

- **GameObject**는 Scene 안에 놓이는 기본 단위입니다. 플레이어, NPC, 카메라, 집처럼 이름과 위치를 가진 대상이라고 생각할 수 있습니다.
- **Component**는 GameObject에 기능을 더하는 부품입니다. 같은 플레이어 GameObject에 이동 Script, 그림을 보여 주는 `SpriteRenderer`, 충돌을 처리하는 `Collider2D` 등을 함께 붙일 수 있습니다.
- **Transform**은 모든 GameObject가 기본으로 가지는 Component이며 위치, 회전, 크기를 보관합니다.

## Inspector와 SerializeField

Inspector는 Unity Editor에서 선택한 GameObject와 Component의 설정을 보여 주는 창입니다.

C#의 `private` 필드는 원래 클래스 밖에서 직접 바꿀 수 없습니다. 필드 앞에 `[SerializeField]`를 붙이면 private 상태를 유지하면서도 Inspector에서 값을 확인하고 수정할 수 있습니다. 플레이어 이동 속도나 NPC 대사처럼 개발자가 Scene별로 조절할 값에 사용합니다.

## 자주 보는 Unity 생명주기 메서드

Unity는 정해진 시점에 특정 이름의 메서드를 자동으로 호출합니다.

- **Awake**: GameObject가 준비될 때 먼저 호출됩니다. 필요한 Component를 찾거나 입력 기능을 만드는 초기화에 사용합니다.
- **Start**: 활성화된 뒤 첫 프레임 전에 한 번 호출됩니다. 다른 오브젝트의 `Awake`가 끝난 다음 시작할 작업에 알맞습니다.
- **Update**: 화면 프레임마다 호출됩니다. 키보드나 게임패드 입력처럼 매 순간 확인할 작업에 사용합니다.
- **FixedUpdate**: 일정한 물리 시간 간격으로 호출됩니다. `Rigidbody2D`를 움직이는 물리 처리에 사용하면 화면 갱신 속도가 달라도 움직임이 일정합니다.
- **LateUpdate**: 일반 `Update`가 끝난 뒤 호출됩니다. 플레이어 이동을 확인한 다음 따라가는 카메라에 알맞습니다.
- **OnEnable / OnDisable**: Component가 켜지거나 꺼질 때 호출됩니다. 입력을 받기 시작하거나 멈추는 데 사용합니다.
- **OnDestroy**: GameObject가 제거될 때 호출됩니다. 직접 만든 입력 객체나 이벤트 연결을 정리합니다.

## 주요 2D 기능

### Rigidbody2D

Unity 2D 물리 이동에 사용하는 Component입니다. `PlayerController`는 위치 값을 곧바로 바꾸는 대신 `Rigidbody2D.MovePosition`을 사용해 플레이어를 움직입니다.

### Collider2D

캐릭터가 벽이나 다른 오브젝트와 부딪히는 범위를 정하는 Component입니다. `BoxCollider2D`는 사각형, `CircleCollider2D`는 원형 범위를 사용합니다. `isTrigger`가 켜진 Collider는 상대를 밀어내지 않고 겹침 감지에 사용할 수 있습니다.

### SpriteRenderer

2D 그림인 Sprite를 Scene에 표시하는 Component입니다. `sortingOrder` 값으로 어떤 그림이 앞이나 뒤에 보일지 정할 수 있습니다.

### Animator와 Animation Clip

`Animation Clip`은 시간에 따라 바뀌는 Sprite 프레임을 보관합니다. `Animator`는 대기, 걷기, 방향 같은 상태를 관리하고 알맞은 Clip을 재생합니다. `PlayerSpriteAnimator`는 플레이어 입력에 따라 `Idle_Down`, `Walk_Left` 같은 상태를 선택합니다.

## Prefab과 Scene

- **Prefab**은 Component와 설정이 완료된 GameObject를 재사용할 수 있게 저장한 Asset입니다. 같은 종류의 NPC를 여러 Scene에 배치할 때 원본 틀로 사용할 수 있습니다.
- **Scene**은 GameObject가 배치된 하나의 게임 화면 또는 공간입니다. 현재 프로젝트는 시작용 `Bootstrap` Scene에서 실제 마을인 `World_StarterVillage` Scene을 불러옵니다.

## Editor Script

`Editor` 폴더의 Script는 Unity Editor에서 개발을 편하게 해 주는 도구입니다. 빌드된 실제 게임에서는 실행되지 않습니다.

Project-Limitless의 Editor Script는 다음과 같은 작업을 자동화합니다.

- `AssetDatabase`로 프로젝트의 Asset을 찾고 생성하거나 저장합니다.
- Sprite 시트를 여러 애니메이션 프레임으로 Slice합니다.
- Animation Clip과 Animator Controller를 만듭니다.
- 플레이어와 NPC Prefab을 만듭니다.
- 마을 Scene을 구성하고 Build Settings에 등록합니다.
- 자동 생성 결과물을 교체하기 전에 백업합니다.

## 코드 폴더별 역할

`Unity/Client/Assets/_Project/Scripts/` 아래 폴더는 역할에 따라 나뉩니다.

- `Scripts/Core`: 게임 시작, Scene 사이의 세션 선택값, 임시 시각 표현처럼 여러 시스템의 바탕이 되는 기능
- `Scripts/Player`: 플레이어 입력, 물리 이동, Male/Female 외형 선택, 방향별 애니메이션
- `Scripts/Camera`: 플레이어를 따라가는 2D 카메라
- `Scripts/NPC`: NPC 데이터, 가까운 NPC 찾기, 대화 상호작용 안내
- `Scripts/UI`: Character Creation과 대화창처럼 화면에 보이는 사용자 인터페이스
- `Scripts/Editor`: Scene, Prefab, Sprite, Animation Asset을 자동 생성하는 Unity Editor 개발 도구

## 현재 플레이 흐름 따라 읽기

처음 읽을 때는 다음 순서가 이해하기 쉽습니다.

1. `BootstrapLoader`가 시작 Scene에서 Character Creation Scene을 불러옵니다.
2. `CharacterCreationController`가 Male/Female 선택을 `GameSessionData`에 기록하고 마을 Scene을 불러옵니다.
3. `PlayerController`가 입력을 읽고 `Rigidbody2D`로 플레이어를 움직입니다.
4. `PlayerVisualController`가 세션에서 선택된 Male/Female Sprite와 Animator를 `Visual` 자식에 연결합니다.
5. `PlayerSpriteAnimator`가 이동 방향에 맞는 그림 애니메이션을 재생합니다.
6. `CameraFollow`가 플레이어 이동 뒤에 카메라 위치를 따라갑니다.
7. `InteractionSystem`이 반경 안에서 가장 가까운 `NpcController`를 찾습니다.
8. `NpcInteractionPrompt`가 현재 대상 NPC 위에 대화 안내를 표시합니다.
9. 상호작용 버튼을 누르면 `DialoguePresenter`가 NPC 이름과 대사를 화면에 표시합니다.

정확한 방향을 맞추거나 제한 시간 안에 버튼을 누르지 않아도 가까운 NPC와 대화할 수 있고, 안내를 글자로 함께 표시하므로 색상만으로 정보를 구분하지 않아도 됩니다. 이는 Project-Limitless의 접근성 원칙을 코드에 반영한 예입니다.
