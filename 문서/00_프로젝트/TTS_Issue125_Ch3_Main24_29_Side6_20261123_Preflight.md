## 3. Stable ID 후보, 충돌, Runtime 상태

**CSV의 `candidate_id`는 사람이 비교할 `PROPOSAL_NOT_RUNTIME` 행 키이며, 출시용 확정 DialogueId가 아니다.** Main 주연은 `main24_serin_001` 등 장면×화자 로컬 번호 제안, 서브는 `ch3_side01_orna_accept` 등 상태 구분 제안. 기존 구현이 `Main24`에 이미 ID를 할당했다면 **그 ID를 먼저 재사용**하며, 제안 ID로 덮어쓰지 않는다.

- 후보 행 키 **101개 고유** / 이번 CSV 내부 동일 ID **0**, 현재 연결 가능한 11/19 안전 checkpoint `backup/2026-11-19-safe-checkpoint`의 [StoryVoiceCatalog 312 IDs](https://github.com/HappyPaul812/Project-Limitless/blob/backup/2026-11-19-safe-checkpoint/Unity/Client/Assets/_Project/Resources/Audio/Voice/Story/StoryVoiceCatalog.asset) (Git Blob `27be73d5630aea9072a18736ae40f240d43927d2`)와 후보 ID **문자열 충돌0**. **해당 Catalog에는 Main22~29로 시작하는 음성 ID 0개**. 이것은 *VoiceCatalog 한정*이며 Dialogue Runtime 구현 전체에 대한 부재 증거가 아니다.
- `docs/planning` 브랜치의 구 `StoryVoiceCatalog`는 280항목으로 현 제품 기준과 다르므로 **거기서 신규 ID 빈자리 280를 기준으로 판단하지 않음**. **최소 312개의 162/162 기존 승인 VoiceCatalog/AudioClip 보존**이 기준. 실제 PC 로컬 원본은 마지막으로 11/19 `main` / 복구 checkpoint와 달라졌을 수 있으므로 **최종 충돌 감사가 반드시 필요**하다.
- 문서 `Chapter3_기획구현현황_20261118.md`: **Main24 F2 왕복·올빼미/한기 일부 Runtime 진행**, 그러나 정식 대사·보상·ID는 구현감사 전. **Main25~29 F3/F4/F5/보스 정식 Runtime 미구현 보고**. 서브6도 `RUNTIME_NOT_IMPLEMENTED`. 따라서 **신규 Voice WAV나 임포트·실기동 합격을 주장 금지**.
