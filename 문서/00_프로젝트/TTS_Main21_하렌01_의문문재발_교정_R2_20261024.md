- 사용자: **“또 의문문이야.”** 세린67/67·태온85/85로 **152/152 WAV READY**가 된 후 하렌 첫 대사를 제작했으나, 정식 평서문 **`태온. 너 아직 멀었어.`**의 “멀었어.”를 또 **끝을 올리는 의문형 운율**로 생성함.
- 파일이 음성으로 존재해도 **`USER_AUDIO_QA=FAIL`**. 하렌 첫 대사 아직 합격/제작완료로 기록하지 말 것. R1 과거 실패와 이번 실패의 파일/메타와 호출 기록 보존.
- **나머지 하렌2개 제작 잠정 STOP**. 구 `Haren_Main21_AfterRenewal_3.py run`은 첫 WAV 파일이 있으면 청취 합격 여부를 판별하지 못하고 다음2개를 제작할 수 있으므로 사용 금지.

## 원인 진단 근거 / 한계

- 현행 하렌용 TTS 코드 `Tools/TTS/Haren_Main21_AfterRenewal_3.py`는 `gemini-3.8-flash-tts:generateContent`에 `contents[].parts[].text`는 **정확한 대사만**, `speech_metadata.style`에 **긴 영어 설명/DECLARATIVE/NOT QUESTION**을 보내고 있음. 이것은 **공식 REST API가 문서화한 구조와 일치**한다. 따라서 `speech_metadata` 자체가 무시되거나 프로그램이 지시를 전달하지 않았다고 확정할 증거가 없음.
- 공식 Gemini 3.8 TTS 가이드는 `text`를 verbatim transcript로 두고 prosody/inflection을 `speech_metadata.style`에서 조정하며, **필요한 경우 간결하고 직접적인 짧은 style**을 권장한다. https://ai.google.dev/gemini-api/docs/generate-content/speech-generation
- **추정 문제:** 실제 음성 모델이 긴 복합 연기 지시보다 문장 내 자연 운율을 우선해 질문형 상승으로 끝낸 것으로 보임. 특정 시스템 버그나 명령 전달 누락으로 확정할 수 없음.
- **R2 변경:** 대사와 VoiceID는 동일하게 유지하되, style을 짧고 직접적인 한국어 하강운율 지시로만 교체. *`낮고 차분한 한국어 평서문으로 단정적으로 이야기한다. 무뚝뚝한 형이 동생에게 담담하게 타이르는 느낌. 마지막 "멀었어."는 "어"로 갈수록 음높이를 명확히 낮추며, 끝을 짧고 확실하게 종결한다. 말끝을 올리지 않는다.`* 이것은 **효과의 보장이 아니라 1회 시험 후보**다.
- 대사 원문 변경·역물음표 삽입·억양 DSP 변형·샘플 속도/피치 조작 없음.

- 포함: `Haren_Prosody_Retake_R2.py` + `README_Haren_Prosody_R2_KO.txt`. API 키/WAV/Unity 파일 없음.
- 사용자 직접 `F:\Downloads\Voice`에 압축 해제. 기존 `Haren_Main21_AfterRenewal_3.py`, `F:\Downloads\Renewal_Voices\Renewal_Auto_TTS_Failover_v2.py`, 설정·기존 공유 장부/4키를 재사용. Script가 새로 4키를 저장·생성하거나 공식 프로젝트 매핑을 추정하지 않음.
- **`check`:** Google POST0, 152완료·기존 첫 WAV·R2 후보·HOLD와 사용자 승인 마커 및 공유 PT 카운트 표시.
- **`retake`:** 정확 ID/정본 텍스트/기존 Bad WAV+meta SHA 보호 확인, 기존 152 완료 및 API 그룹/한도/유효 무료 과금 상태 확인, 사용자 **`RUN_RETAKE_01` 입력 후에만 최대 POST 1회**. 기존 공식 Bad 음성은 덮어쓰지 않음. 생성 샘플:
  `F:\Downloads\Voice\Haren_Main21\ProsodyRetakes\R2\Haren\main21_haren_haren_01.wav`.
  같은 워크스페이스 `.json` metadata와 SHARED PT `ATTEMPT`/`SUCCESS` 기록, 기존 HOLD/LOCK·429 보호 로직 재사용.
- **R2 실제 청취 FAIL:** `python .\Haren_Prosody_Retake_R2.py reject-r2` → R2 샘플 보존, 추가 TTS 요청0, R3 운율 지시/음성 후보 재검토 전 멈춤.
- **R2 실제 청취 PASS:** `python .\Haren_Prosody_Retake_R2.py approve` → 사용자 **`APPROVE_FALLING_R2`**를 직접 입력한 뒤 기존 공식 불합격 WAV+메타를 SHA 검증해 `F:\Downloads\Voice\Haren_Main21\rejected\...`에 백업하고, R2 후보를 공식 WAV+메타로 교체. 승인 마커 `HAREN_01_APPROVED.json`와 감사 이벤트 생성. **R2를 실제 듣지 않고 승인 금지.**
- 하렌 첫 음성 최종 청취 승인 마커의 WAV SHA가 정확히 유효할 때만 `python .\Haren_Prosody_Retake_R2.py remaining`으로 **나머지02/03 생성 허용**, 기존 `RUN_HAREN3` 수동 승인/공유 장부 내 안전예산 적용. 02/03도 각각 청취 QA와 사용량 확인. `Haren_Main21_AfterRenewal_3.py run` 직접 실행하지 말 것.
- 네 키가 실제 서로 다른 Google 프로젝트인지, Google 모델별 실제 무료 잔여/과금 상태는 사용자 별도 확인. `40`은 로컬 예산, 외부 Google 서버 성공·청구보장 아님. 모든 생성은 **사용자 직접 PowerShell 실행**, Codex 생성/키 사용 금지.
