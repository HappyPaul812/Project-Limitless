# Chapter3 냉기 상태와 보스 화로 — 2026-10-12

**확정 기획 / 런타임 미구현.** 현재 [전투 시스템](전투시스템.md)의 과열·독·화상·침묵을 변경하지 않는다. [스킬·해제 대응표](../06_스킬/Chapter3_스킬상점_강화_냉기_동결괴사_20261012.md)와 함께 구현 준비 기준으로 사용한다.

## 서로 독립적인 상태

| 상태 | 확정 효과 | 남은 결정 |
|---|---|---|
| 한기 | 2턴 동안 **전체 행동 불가** | 자기 행동 기회 기준 감소의 정확한 순서·재적용·중복 부여·큐 정리 |
| 동상 | 한기 효과(2턴 행동불가) + HP 감소 | HP 감소량·틱 시점·재적용·중복 규칙 |
| 동결괴사 | 대상별1→2→3 독립 중첩, **3번째 적용 즉시 HP0·전투불능** | 보스 패턴·대상 선정·저항/면역·중첩 빈도 |

한기는 침묵과 다르다. 침묵은 스킬만 막지만 한기는 공격/스킬/아이템/방어/화로를 포함한 행동을 못 한다. 동상은 별도로 부여하는 상태이며 한기가 쌓여 자동 진화하지 않는다. 동결괴사도 한기/동상의 누적 진화가 아니다. 동상의 HP 감소를 현재 독/화상과 같은 틱이라고 임의 확정하지 않는다.

동결괴사는 보스 스킬 전용이다. 1/2중첩만으로 추가 행동불가를 부여하지 않는다. 3중첩은 영구 사망/Save 삭제가 아닌 기존 전투불능이다. KO·전투 종료·새 전투에서 중첩을 정리한다. 현재 과열은3중첩에서 ceil(MaxHP×0.08), 최소1 피해 후0으로 별개다. 과열 코드를 단순 복사해 동결괴사의 피해 감소/방어 적용 여부를 묵시적으로 정하지 않는다. 신규 즉시KO는 실제 KO 정리·파티 자원·승패 판정 경계를 재사용하도록 준비한다.

## 온기의 화로: 전투 화면의 상호작용

화로는 Boss Battle Scene의 전투 화면에 배치한다. 자유 이동 Field의 시설이 아니다. 행동 가능한 아군의 자기 차례에 `화로 사용` 명령 → 살아 있는 아군1명 선택 → 그 대상의 동결괴사 중첩 전체 제거 → **행동1회 소비**. 아이템·탈렌트 소비0, HP 회복0, 부활0. 자신도 살아 있고 행동 가능하면 대상 후보가 될 수 있도록 검토하되 대상 UI 범위의 상세는 구현 전 확정한다.

1/2중첩 대상이 대응 대상이다. 이미3중첩으로 전투불능이면 화로가 되살리지 않으며 치유사의 부활이 필요하다. 중첩 없는 대상·전투불능 대상·잘못된 선택·취소는 행동을 쓰지 않고 설명 후 선택/명령으로 복귀한다. 한기/동상으로 행동불가한 사용자는 화로를 쓸 수 없다. 살아 있지만 행동불가한 **대상**은 다른 행동 가능한 동료의 도움을 받을 수 있어야 한다.

지속적으로 대응에 사용할 수 있는 방향을 유지한다. 화로의 시각 UI·아이콘·효과·별도 쿨타임의 구체 계약은 TBD이며 숫자를 임의 도입하지 않는다. 일반전에서는 해당 보스 기믹 명령을 노출하지 않는다. 기존 공격/스킬/아이템/방어/도망 명령·보상·InputAction을 보호한다.

## 공정성과 접근성

동결괴사 1/3·2/3 및 위험 경고를 텍스트+아이콘으로 표시하고 색상만으로 알리지 않는다. 화로의 효과·행동 소비·대상을 선택 전에 설명한다. 빠른 반응이나 짧은 시간 제한을 요구하지 않는다. 대상 선택·취소·결과 안내를 기존 입력 장치에서 접근 가능하게 준비한다.

**세 번째 중첩 전에 최소1회의 실제 유효 대응 행동을 보장**해야 한다. 단순히 '한 턴 있었다'는 이유만으로 모두 한기 상태인 파티의 대응을 보장했다고 판정하지 않는다. 보스/아군 민첩과 큐·3인 파티·치유사 미편성·한기/동상 조합·최후 생존자에서 화로 또는 적절한 대응이 실제로 가능해야 한다. 무작위 대상으로 회피 불가능한 즉사/전원 행동불가 교착을 만들지 않는다. 정확한 패턴과 수치는 승인 전 설계·시뮬레이션 대상이다.

## 코드 연결점과 구현 순서 제안

이번 런타임 변경0. `BattleSkillSystem.cs`의 BattleStatusEffectRuntime/정화, `BattleSceneController.cs`의 현재 행동자·명령/대상 선택·행동 완료, `TurnOrderQueue`의 생존/행동 순서, `BattleCombatantStatusViewModel.cs`의 HUD, `Combatant`의 피해/KO 및 `PartyResourceService`의 전투 결과 기록을 함께 점검한다.

상태 데이터와 행동 차단을 먼저 분리 설계 → 해제 대응표/부활 대상 계약 → 보스 패턴·공정성 → 화로 UI → 구버전 Save/파티/기존 전투 회귀 순으로 준비한다. 새로운 상태 ID·스킬 ID·Scene·Quest를 만들지 않는다. 전투 전용 임시 상태를 월드 Save에 새로 저장할지는 TBD이며 현재 SaveVersion1을 수정하지 않는다.
