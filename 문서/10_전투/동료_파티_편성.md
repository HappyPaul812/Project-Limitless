# 동료 명단과 솔로 파티 편성

## 데이터와 정책

- 단일 `CompanionRosterService`가 해금 ID·활성 동료 ID·편성 행을 관리한다. Player는 항상 포함하고 교체 불가, 동료는 최대 2명이다. 이 제한은 솔로 편성 정책이며 Battle의 2×3 Formation이나 향후 6+α 확장을 제한하지 않는다.
- `Resources/CompanionDefinitions`의 동료 데이터가 이름·직업·길·기본 행·기존 전투 수치를 연결한다. UI는 정의와 해금 ID를 조합해 동적으로 목록을 만들며 3인 전용 고정 명단이 아니다. 기존 `companion_paul` Visual·Animator·Portrait·Mage 스킬을 복제하지 않는다.
- Main05: 태온·미엘 해금, 기본 Player+태온+미엘. Main09 마지막 대화 완료: 폴 해금.
- 폴 최초 해금 시 Guardian는 미엘+폴, Healer는 태온+폴, Sharpshooter/Fighter/Mage는 태온+미엘을 기본 선택한다. 기존 UI에서 확정한 편성(`HasManualComposition`)은 덮어쓰지 않는다. `PaulDefaultApplied`와 해금 ID로 중복 적용을 막는다.
- 추천은 선택 제한이 아니다. 해금된 동료라면 직업·길과 무관하게 선택할 수 있으며 동료 0~2명 편성도 허용한다.

## 안전지역 UI

- 기존 `starter-village-party-manager` 파티 안내인에 `PartyManagementPresenter.OpenAt`을 연결한다. 현재 허용 지역은 `World_StarterVillage`; Field/Battle 진입과 단축키는 제공하지 않는다. 향후 캠프는 안전지역 진입 정책만 확장하고 명단·편성 서비스와 UI를 재사용한다.
- 현재 편성, Player 고정, 동료 이름·초상화·직업·길·선택 체크·전열/후열을 표시한다. 목록은 스크롤 가능하며 미해금 동료는 제외한다.
- 이름 버튼은 선택/해제, 배치 버튼은 전열/후열 전환이다. Player 행도 바꿀 수 있다. 초안은 확정 시에만 저장하며 취소는 원본을 유지한다.
- `WorldModalState`, Player 이동 잠금, World HUD 숨김을 기존 방식으로 재사용한다. Dialogue·Shop·Inventory·Quest Log와 상호 배제한다. 취소 버튼·Esc·게임패드 B·Scene 종료에서 해제한다.
- Tab/Shift+Tab, 방향키/게임패드 UI 탐색, Enter/Space/게임패드 A를 사용한다. 색뿐 아니라 `[✓ 선택]`·`[미선택]`·`[고정]`과 전열/후열 글자를 표시한다.
- Player 포함 전체 파티에 사수·투사·마도사가 없으면 “공격 역할의 동료가 없습니다. 전투 시간이 길어질 수 있습니다.”를 표시한다. `그래도 편성`을 허용하고 `돌아가기`는 초안으로 돌아온다.

## Formation과 Battle

- 기존 `FormationRow`·`FormationSlot`을 사용한다. Save에는 CharacterId와 Row를 저장하고 Column은 Player→선택 동료 순서에서 같은 행의 앞사람 수로 0~2를 부여한다. 같은 행 세 명도 중복되지 않는다.
- Normal Encounter는 저장 편성을 읽어 참가자를 만든다. Player+태온+폴에 미엘을 임의로 추가하지 않는다.
- Main03/04/07 Story Factory는 원래 고정 임시 참가자를 유지하며 명단·수동 선택·Formation 저장을 수정하지 않는다. Main07의 미엘 제외와 Player·태온·폴을 유지한다.
- Battle 진입 후 Formation 편집은 없다. 편성 변경은 HP/MP를 초기화하지 않으며 같은 CharacterId의 기존 `PartyResourceService` 상태를 재사용한다.

## 저장 호환

- Save Version1에 `CompanionRoster.Formation`, `HasManualComposition`, `PaulDefaultApplied`를 선택 필드로 추가한다.
- 이전 Save에 Formation이 없으면 Player·태온은 Front, 미엘·폴은 Rear 기본값을 쓴다. null 배열·유효하지 않은 행은 안전 기본값으로 처리한다.
- 기존 해금·활성 ID는 유지한다. roster 필드가 없는 완료 기록은 Main05/Main09 완료 여부에서 해금을 복원한다. 완료 기록 없는 이전 진행은 동료를 조기 해금하지 않는다.
- 테스트 `Main09PartyAudit`는 Editor 전용 별도 `UserData/Main09Audit/<고유ID>`에서 실제 Save/Bootstrap/Continue를 실행한다. 사용자 `UserData/Saves`는 변경하지 않는다.
