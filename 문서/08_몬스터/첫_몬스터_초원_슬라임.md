# 첫 몬스터: 초원 슬라임

## 목적

`Field_01` 중앙 야외 지역에 첫 필드 몬스터를 배치하고 플레이어 접촉을 1차 턴제 전투로 연결한다. 필드에서는 데이터 기반 배치, 느린 배회와 장애물 충돌을 유지하고 HP·공격·전투불능 판정은 별도 Battle Scene에서 처리한다.

## 데이터 구조

- `MonsterDefinition`: 몬스터 ID, 표시 이름, 필드 이동 속도, 대기 시간과 Visual을 보관한다.
- `FieldMonsterSpawnDefinition`: 대상 Scene, 배치 ID, 몬스터 종류, 시작 위치, 활동 반경과 처치 후 리스폰 시간을 보관한다.
- `FieldMonsterInstaller`: Scene 로드 시 `Resources/MonsterSpawns`에서 현재 Scene과 일치하는 배치를 읽고, 스폰별 런타임 상태에 따라 독립적으로 생성·리스폰한다.
- `MonsterFieldController`: 시작 위치 주변 배회, Rigidbody2D 이동, 장애물 충돌과 플레이어 접촉 정지를 담당한다.
- `MonsterNameplate`: 공용 Screen Space Overlay Canvas에서 몬스터의 머리 위를 따라다니며 `DisplayName`을 표시한다.
- `MonsterEncounterService`: 접촉한 `MonsterDefinition`과 정확한 스폰 데이터를 Event로 전달하며, 스폰별 처치 만료 시간과 전투 복귀 직후의 짧은 재조우 유예를 관리한다.

새 몬스터 종류는 `MonsterDefinition`, 새 배치는 `FieldMonsterSpawnDefinition` Asset을 추가하여 기존 Controller를 재사용한다. `BattleSceneFlow`가 `MonsterEncounterService.EncounterStarted`를 구독해 별도 Battle Scene과 재사용 가능한 전투 데이터 구조로 연결한다.

## Field_01 배치

- 몬스터 종류: 초원 슬라임 (`grass_slime`)
- 배치 수: 5개 (`grass_slime_01`~`grass_slime_05`)
- 시작 위치: `(2.5, 0)`, `(-5, 3.5)`, `(-4, -3.5)`, `(5.5, -3.3)`, `(6, 2.2)`
- 활동 반경: 배치별 `1.5~1.8`
- 처치 후 리스폰: 배치별 기본 `30초`
- 필드 이동 속도: 초당 `0.8` 월드 단위
- 이동 사이 대기: `0.8~2초`

다섯 배치는 북쪽 Spawn/복귀 Trigger와 떨어진 여러 빈터에 분산한다. 각 슬라임은 자기 시작 위치 중심의 활동 반경 안에서 독립적으로 목적지를 선택하며, 범위 밖으로 밀리면 자기 중심 복귀를 우선한다.

### 독침벌 추가 배치

- 몬스터 종류: 독침벌 (`venom_bee`)
- 배치 수: 3개 (`venom_bee_01`~`venom_bee_03`)
- 시작 위치: `(-8, -1.5)`, `(0, 5)`, `(8, -5.5)`
- 활동 반경: 각 `1.25`
- 처치 후 리스폰: 각 `30초`
- 표시 Scale: 검증 완료값 `0.85`

독침벌 세 개체는 기존 슬라임 다섯 개체와 같은 설치기·배회·조우·독립 리스폰 흐름을 사용한다. `FieldMonsterSpawnDefinition`은 필드의 위치와 개체 상태를, `MonsterDefinition`은 독침벌 종류와 공용 SpriteSheet를 나타내므로 같은 독침벌 정의를 여러 스폰과 Battle에서 안전하게 재사용한다. 이번 단계에는 이름과 외형만 독 콘셉트이며 독 상태이상 판정은 포함하지 않는다.

## 독침벌 Visual과 Animation

`02_VenomBee.asset`이 프로젝트에 보존된 Pilot Bee Idle/Attack 원본 복사본과 프레임 구조를 참조한다. `MonsterSpriteSheetAnimation`은 원본 PNG를 수정하지 않고 실행 중에 Idle 10프레임과 Attack 10프레임으로 나눈다. Field에서는 이동 중에도 공중 생물의 날갯짓 Idle을 반복하고, Battle에서는 기본 공격 시작에 Attack으로 전환한 뒤 행동 완료 시 Idle로 복귀한다. 원본은 오른쪽을 바라보므로 적이 오른쪽의 아군을 보는 Battle 배치에서는 뒤집지 않는다.

## 필드 Visual과 Animation

사용자가 제공한 4×4 방향별 Sprite 시트를 실제 필드 Visual로 사용한다. 원본 1254×1254 이미지는 그림 크기를 바꾸지 않고 오른쪽과 아래에 각각 2픽셀의 투명 Padding을 추가하여 1256×1256으로 맞췄다. 각 314×314 Cell은 위에서부터 Down, Left, Right, Up 방향이며 각 행의 첫 프레임은 Idle, 네 프레임 전체는 약 6 FPS의 반복 Walk Animation에 사용한다.

- 최종 PNG: `Assets/_Project/Art/Monsters/01_GrassSlime/01_GrassSlime_Walk.png`
- Animator/Animation: `Assets/_Project/Animations/Monsters/01_GrassSlime/`

`GrassSlimeAnimationBuilder`가 PNG Import 설정, 16개 Sprite Slice, Idle 4개, Walk 4개와 `GrassSlime.controller` 생성을 재현하고 결과를 `01_GrassSlime.asset`에 연결한다. 런타임의 `MonsterFieldController`는 기존 배회 목적지로 향하는 방향과 이동·대기 상태에 맞춰 Animator 상태를 선택한다.

## 필드 이름표

`MonsterNameplate`가 `MonsterDefinition.DisplayName`의 `초원 슬라임`을 머리 위에 표시한다. 플레이어 이름표와 같은 Screen Space Overlay 방식을 사용하며 흰색 글자와 검은 외곽선으로 배경 위 가독성을 확보한다. 필드에서는 HP Bar를 표시하지 않으며, HP는 향후 전투 UI에서만 다룬다.

## 조우 경계

플레이어와 처음 접촉하면 슬라임은 이동을 멈추고 `MonsterEncounterService`가 몬스터 종류와 정확한 `FieldMonsterSpawnDefinition`을 `EncounterStarted` Event로 전달한다. `BattleSceneFlow`는 현재 플레이어 외형, 스폰 ID와 필드 접촉 위치를 보관한 뒤 `Battle` Scene으로 이동한다. 승리하면 조우한 스폰만 필드에서 제외하고 해당 데이터의 기본 30초가 지난 뒤 원래 시작 위치에 다시 생성한다. 다른 스폰은 영향을 받지 않는다. 도망 또는 패배는 스폰을 제거하지 않고 전투 HP·상태만 초기화한다. 모든 필드 복귀는 플레이어를 접촉 지점에서 떨어뜨리고 2초간 조우를 유예한다.
