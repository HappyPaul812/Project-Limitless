# Main21 자동 귀환 마차 — 설계 및 구현 준비

2026-10-10 · 사용자 기획 전제 확정 / **이번 단계 문서화만 완료, Runtime 미구현**

목표는 Main21 중 아르벨에서 초보 마을로 돌아오는 구간을 짧고 스킵 가능한 일회성 마차 이벤트로 처리하는 것이다. 아트 수령 후 이 문서를 바탕으로 구현·QA한다. Main21 전체 Quest/Objective/Dialogue는 아직 미확정이며 아래 새 이름·ID·시간·배치·기술 방식은 명시된 경우 외에는 **구현 후보/권장안**이다. 이번에 Scene·Script·Trigger·Quest Asset·placeholder·음성을 생성하지 않았다.

## 확정된 기획과 범위

2026-10-10 후속 [Main21 「돌아온 온기」 초안](Chapter2_Main21_돌아온_온기.md)의10번째 목표가 이 자동 귀환을 참조한다. 접이식 램프·내부 고정 공간·동료 좌석은 최신 사용자 요구 조건이며 아래 승강 구조 후보보다 우선한다. 실제 마차 아트는 아직 제작되지 않았고 전체13목표의 ID/유형/좌표/보상과 구현 승인은 대기한다. 아트 수령만으로 구현을 시작하지 않는다.

- 아르벨 → `World_StarterVillage`는 직접 모든 필드를 역주행할 필요 없는 Main21 전용 자동 귀환이다. 실제 Field를 실시간 주행하거나 범용 빠른 이동/Portal/지역 선택 UI를 만들지 않는다.
- 마차는 스토리 일행의 귀환 수단이다. **항상 접근 가능한 마차1종**, 최대 휠체어2대(폴 + 지체의 길 플레이어)를 수용한다. 일반/휠체어 버전으로 나누거나 Path로 탑승을 제한하지 않는다.
- Main21 주요 일행은 플레이어·폴·미엘·태온·세린 총5명이다. 2대의 휠체어와 나머지 승객의 공간·동선이 함께 성립해야 한다. 탑승자5명은 전투 편성이나 화면 Follow AI가 아니다. 기존 **플레이어1+동료2=전투3인**과 사용자의 편성을 유지한다.
- 흐름: 귀환 제안 → 플레이어 Yes/No → 짧은 자동 연출 또는 Skip → 안전한 초보 마을 도착 → 다음 Main21 목표. No는 이번 출발을 보류하며 퀘스트 실패·영구 거절이 아니다.
- Main21은 Chapter2 마지막, Main22부터 Chapter3. 서부 안정화 조사 → 귀환 → 짧은 폴·미엘 Slow Burn → 북쪽 징후 조사 → 태온 형 첫 만남 → 북쪽 준비의 기존 방향을 유지한다. 귀환을 새로운 연속 대사 구간으로 늘리거나 마차 전투를 추가하지 않는다.

관련 정본: [Chapter2 서부 방향](Chapter2_서부_방향.md) · [팀 공통 인물 정본](../04_등장인물/동료_형제애_바이저_팀공통정본_20261010.md) · [Path 반응형 Story](Path_반응형_Story_연출_규칙.md) · [로컬 저장](../14_저장시스템/README.md).

## 사용 Scene / Script / Trigger 후보

**우선 권장안: Arbel 안의 Main21 전용 연출 구간(UI/배경 스크롤 Overlay).** 실제 플레이어·월드 좌표는 안전한 아르벨 위치에 유지하고 별도 표시용 마차만 움직인다. 종료 시 기존 Scene 전환으로 초보 마을에 간다. 사용자의 “별도 귀환 Scene 또는 간단한 전용 연출 구간” 중 후자를 사용한다.

| 방식 | 장점 | 조건·위험 / 판단 |
| --- | --- | --- |
| Arbel 전용 Overlay/연출 Prefab | 임시 Scene/좌표가 Save에 들어가지 않음, Build 목록 변경 불필요, 기존 Scene 큰 변경 없이 연출 교체 가능 | 입력·모달·BGM·가림 화면의 소유권을 명확히 관리. **1순위 권장** |
| `Story_Main21_CarriageReturn` 별도 Scene | 배경·카메라 구성 독립 | 임시 Scene Save 차단과 마지막 안전 월드 보존, Build 등록/복원 정책이 추가로 필요. **후보, 미채택** |

별도 Scene에 그대로 `SceneTransitionService.Load`를 쓰면 Session의 CurrentSceneId가 연출 Scene으로 기록된다. Save의 비월드 Scene 제외 목록은 현재 정해진 이름 목록이므로 새 이름이 자동으로 제외되지 않는다. `PlayerController`/Bounds가 있으면 주기 저장도 시작된다. 이 방식 채택 시 연출 Scene 저장 거부와 이전 안정적 월드 체크포인트 보존을 먼저 구현해야 한다. 이번 권장안은 이 추가 변경을 피할 수 있다.

후속 후보 경로(아직 파일 없음):

- `Scripts/World/Chapter2Main21Flow.cs`: Main21 현재 단계 확인, NPC 처리·Runtime 설치·도착 복구. Main21 전체 상세가 정해진 후 책임 범위를 확정.
- `Scripts/World/Main21CarriageReturnController.cs`: Main21 전용 상태·중복 방지·연출·Skip·정리·도착 검증. 범용 TravelService로 확장하지 않음.
- `Prefabs/Story/Main21CarriageReturn.prefab`: 마차/배경/자막·Skip 버튼 표시. 실제 Player/Companion 오브젝트와 전투 편성은 변경하지 않음.
- `Scripts/Editor/Main21CarriageReturnAudit.cs`: 후속 격리 Runtime 검증. 이번 생성/실행0.
- NPC 명시적 상호작용 또는 마차 탑승 지점 `Interact`를 이벤트 Trigger로 사용. 접촉 즉시 출발하는 출구 `SceneTransitionTrigger`는 탑승 제안을 대체하지 않음. 기존 `QuestNavigationTarget`·NPC Marker를 조건부 연결.

무거운 카메라 흔들림·빠른 점멸·멀미를 유발하는 큰 스크롤은 피한다. 낮은 움직임/일시정지 선택을 검토하며, 소리가 없어도 자막과 시각 정보만으로 귀환을 이해하게 한다. 일시정지는 연출 타이머와 관련 음성/음악 처리 범위를 함께 정의한다. 시간 경과를 위해 전역 `Time.timeScale`을 변경하지 않는 안을 권장한다.

## 접근 가능한 탑승과 아트 요청 목록

폴과 지체의 길 플레이어가 **각자 휠체어를 사용하는 상태로** 탈 수 있는 구조다. 두 사람을 자동으로 들어 옮기거나 휠체어를 지워 보행 Sprite로 바꾸지 않는다. 도움 여부는 당사자 선택을 존중하고 기본 탑승을 구조적으로 가능하게 표현한다. 일반 Player에서도 같은 마차를 사용하고 빈 공간이 있다고 별도 모델로 교체하지 않는다.

| 아트 | 필요한 정보 / 교체 계약 |
| --- | --- |
| 접근 가능한 마차 본체 | 승객5·휠체어2의 실내 공간과 출입 폭이 모순되지 않는1종. 바퀴/차체/탑승구 레이어 분리는 선택. 최종 크기·색·외형 미정 |
| 접이식 램프·내부 고정 공간 | 최신 사용자 요구 조건. 램프는 탑승용 펼친 상태·주행용 접힌 상태, 휠체어2대 공간/내부 고정과 동료 좌석을 표현. 최종 치수·형태는 아트 담당과 후속 확정 |
| 이동 표현 | 본체 정지 PNG + 배경 스크롤로도 시작 가능. 바퀴 애니메이션, 말/견인 표현, 먼지 효과는 선택이며 마차를 견인하는 설정·종류는 미정 |
| 귀환 배경 | 서부 출발→이동→초보 마을 도착을 읽을 수 있는 배경/전경 반복 레이어. 실제 모든 Field 타일을 제작할 필요 없음 |
| 승객 표시 | 필요 시 기존 공식 인물/Path 외형 재사용 가능한 표시 지점. 폴과 지체의 길 Player가 동시에 탑승하는 설명·구조 확인. 전원 Follow/새 캐릭터 애니메이션은 필수 아트 아님 |
| 선택 사항 | 탑승/정차 강조·효과음·BGM/TTS. 기존 음원 보호, 새 제작은 별도 확정 |

후속 신규 Art 후보는 `Assets/_Project/Art/Story/Main21Carriage/`. 원본 PNG 비율/픽셀과 공식 Player·폴 외형을 보존하고 신규 GUID를 사용한다. 마을 기준 PPU128·Point·Mipmap Off·무압축을 **권장**하되 Canvas/연출 방식·최종 캔버스 치수·Pivot·정차 접지선은 아트 계약에서 확정한다. 월드 Collider 크기를 PNG 크기로 자동 결정하지 않는다.

**Placeholder 준비 가능**: 회색 도형 마차·탑승구·경사로·휠체어2대 자리와 단순 배경으로 시간/Skip/전환 계약을 검증할 수 있다. 최종 Sprite 참조·레이어·탑승/접지 Anchor만 바꾸면 되고 Quest/Save 로직은 그대로여야 한다. Placeholder로 최종 접근성 외형/수용 공간/가독성 PASS를 선언하지 않는다. 이번에는 placeholder도 실제 적용하지 않았다.

## 이벤트 상태·Quest·Save/Continue 권장 계약

새 Quest ID·Objective ID·Target ID는 Main21 전체 설계와 함께 확정한다. 아래 의미를 고유 ID로 나눌 것을 권장한다. 새 Save 전용 boolean을 무조건 추가하지 않고 기존 Quest Objective 진행 저장을 우선 검토한다.

| 상태 | 진입/행동 | 저장·진행·복구 |
| --- | --- | --- |

도착은 Main21 전체 완료/Chapter3 시작 신호가 아니다. 도착 목표 뒤에 기존 후일담 목표를 이어 붙이고 귀환 자체가 Quest의 마지막 목표가 되지 않도록 전체 설계에서 확인한다. 별도 EXP/탈렌트·HP/MP 회복·동료 해금/편성 변경은 추가하지 않는다.

**이어하기 복구 경계:**

1. 수락 전/No: 저장한 Arbel 상태, 다시 제안 가능.
2. 수락 체크포인트 후 주행/Skip/로드 중 종료: 마지막 유효 Arbel 저장에서 귀환 대기 단계로 복구. 재개는 명시적 선택, 자동 출발·필드 역주행 강요 없음.
3. 목적 Spawn 저장 후 도착 Objective 저장 전 종료: `CurrentSceneId=World_StarterVillage` + **Main21 전용 SpawnPointId** + 저장된 수락 단계 + 현재 귀환 도착 목표를 모두 확인해 도착을1회 복구한다. 일반 `Spawn_From_Field01` 수동 진입만으로 마차 완료를 오인하지 않도록 전용 ID를 권장한다.
4. 도착 완료 뒤: 기존 Continue 좌표/다음 목표를 유지, 연출 재생0. 슬롯1~5 중 현재 슬롯만 저장하며 다른 슬롯은 변하지 않아야 한다.
5. 구버전 Main20 완료 Save: Main21 정의 추가 후 선행 조건으로 시작 가능한지 검증. 기존 Quest/Objective ID를 재사용하거나 Version1 저장을 재생성하지 않는다. Main21 전체 정의/자동 시작 연결은 별도 확정·구현.

현재 `QuestService`는 진행 이벤트 뒤 자동 원복을 제공하지 않고 `GameSaveService.SaveCurrentSession()`은 bool로 성공을 반환한다. 또한 도착 Spawn이 먼저 위치를 저장한다. 따라서 **수락 실패 시 이번 Objective만 안전하게 되돌리는 범위**, **도착 저장 실패 시 재시도와 재실행 복구**를 구현 단계에서 명시해야 한다. 전역 QuestProgress 초기화·다른 퀘스트 진행 원복·다른 슬롯 삭제/덮어쓰기로 해결하지 않는다. 메모리의 일반 bool/연출 코루틴만으로 이어하기 안전성을 충족했다고 판단하지 않는다.

## 입력·오디오·실패 처리와 위험

- Yes의 callback에서 대화 `Hide`로 기존 모달 소유권을 정리하고 마차 소유권을 확보한다. 확보 실패는 출발/Quest 변경 전에 중단. No/Esc는 기존 Hide와 함께 아무 진행도 하지 않는지 검증한다.
- 이동은 소유자 잠금으로 제어, 상호작용·출구·전투 진입을 포함해 경합을 확인한다. `WorldModalState`는 모든 입력을 자동 차단하는 전역 장치가 아니다. 마차 모달 중 상점/은행/메뉴 단축키·Interaction Esc가 Skip UI를 닫아 버리는 문제를 별도 가드해야 한다.
- 선택/주행/정리 중 Rigidbody 잔여 이동·받아 둔 입력을 소거하고 같은 프레임 수락이 Skip/새 NPC 상호작용으로 재전달되지 않게 한다. 기존 소유자의 잠금을 `Reset`으로 일괄 해제하지 않는다.
- 정상/Skip/오류/OnDisable/OnDestroy에서 마차 UI·모달·이동 잠금·Coroutine·오디오 임시 상태를 소유자 기준으로 정리한다. Scene이 성공적으로 준비되기 전에 기존 World를 자유 이동 상태로 해제하지 않음. 실제 실패 시에는 안전한 기존 상태를 복구하고 다시 시도할 수 있어야 함.
- 로드 불가 Scene/누락 Spawn/Player 생성 지연: 출발 전 Build 설정 확인, 배치 성공 재확인, 중복 요청 가드·타임아웃/예외 처리 필요. 현재 서비스의 `isLoading`이 실패 뒤 남는 위험에 대해서는 호출자에게 결과/실패 정리를 전달하는 **작은 확장 후보**를 검토; 기존 출구 호출 계약은 유지한다.
- BGM은 Arbel→주행→초보 마을 전환/페이드 후보. 기존 사용자 BGM/SFX/Voice 음량·음소거 설정은 변경/저장하지 않는다. 기존 private Transition을 공개된 것으로 가정하지 말고 마차 요청용 최소 공개 진입점 또는 전용 연출 Source를 검토. Scene의 일반 `ApplyScene`과 중복 곡/페이드 충돌을 검증한다. 곡과 페이드 수치는 미정이다.
- 전용 도착 Spawn은 Runtime 설치/중복 가드로 기존 Scene 재생성을 피한다. (0,-4.65)는 현재 남문 Trigger와 분리돼 있지만 최종 마차가 통로/NPC/Bounds를 막지 않는지는 미검증이다.
- StarterVillage v2 아트는 현재 `NEEDS_ART_CORRECTION`이다. 이번 마차 준비로 마을 리뉴얼이 적용됐다고 가정하지 않고 현재 LOCAL Scene으로 후속 QA한다.

## 후속 구현 순서와 백그라운드 QA 계획

1. 제공자·정차 위치·Main21 선행/수락/도착/다음 Objective·Stable ID·대사·10~15초 컷 구성을 확정한다. 범용 이동 기능으로 범위를 넓히지 않는다.
2. 수락/Skip/도착복구 상태와 저장 실패 처리를 작은 코드로 구현하고, 전용 표시 Prefab/placeholder로 먼저 비대화형 검사한다. 아트는 필드 참조로 교체 가능하게 분리한다.
3. 아트 수령 후 CRC/디코드/alpha/치수/PPU/Pivot/탑승구·휠체어2대·레이어 접합 검수, 신규 전용 폴더로 Import한다. 기존 캐릭터/무료 에셋/마을 Scene 원본 교체 범위와 분리한다.
4. 안전한 도착 Spawn·NPC/Nav/Marker를 현재 LOCAL 마을에서 검증하고 정상/Skip 공용 경로를 연결한다. 임의 Scene Generator 실행0.
5. 격리 프로젝트·격리 Save 경로에서 Unity6.6.5f1 Batch/Edit/Play 테스트와 RenderTexture 캡처. 실행 중 기존 Editor를 강제 종료/Play/Scene 전환하지 않는다. 추가 Editor는 승인 없이 실행하지 않는다. 불가능한 검사는 NOT_VERIFIED로 남긴다.

## 이번 단계 검증 상태와 미정 항목
