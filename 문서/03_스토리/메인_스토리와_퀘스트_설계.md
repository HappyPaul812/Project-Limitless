# 메인 스토리와 퀘스트 설계

## 상태

🟢 기본 구조 및 1장 도입 방향 확정

## 문서 목적

LIMITLESS의 공통 메인 스토리, 길에 따른 변주 원칙, 1장 초반 메인 퀘스트의 방향을 기록한다. Main 01의 대사·퀘스트 데이터·보상은 확정했으며, Main 02 이후의 실제 데이터와 사건의 최종 원인은 후속 설계에서 확정한다.

## 전체 스토리 구조

LIMITLESS는 **하나의 세계와 하나의 중심 메인 스토리**를 공유하며, 플레이어가 선택한 길에 따라 장면·대사·개인 에피소드가 달라지는 구조를 사용한다.

- 메인 사건, 주요 지역 진행, 주요 NPC와 사건의 핵심 결과는 모든 길에 공통이다.
- 공통 장면 안에서 `PathId`에 따른 짧은 대사나 반응을 보여 준 뒤 다시 공통 진행으로 합류할 수 있다.
- 챕터 사이에는 해당 챕터의 주제와 선택한 길을 더 깊게 다루는 길 전용 개인 에피소드를 둘 수 있다.
- 다른 길에서만 볼 수 있는 장면은 존재할 수 있지만, 메인 퀘스트 다섯 벌을 별도로 만들지는 않는다.

예시 구조는 다음과 같다.

```text
Main_01 → Main_02 → Main_03
                    ↓
              PathEpisode_01
              ├─ EmotionalScar
              ├─ Hearing
              ├─ Vision
              ├─ Mobility
              └─ Intellectual
                    ↓
              Main_04 → Main_05
```

## 길에 따른 서사 변화 원칙

길은 캐릭터가 살아온 경험, 세계를 받아들이는 방식, 관계를 맺는 방식과 상황을 해석하는 관점에 영향을 줄 수 있다. 그러나 길이 성격 전체나 운명을 결정하지 않는다.

- 장애나 상처를 특정 성격·행동과 일대일로 고정하지 않는다.
- 장애를 초능력처럼 특별한 정보를 얻는 원인으로 사용하지 않는다.
- 특정 길만 더 좋은 정보, 결말, EXP, 탈렌트 또는 아이템을 얻지 않는다.
- 길별 장면과 선택지는 표현과 경험을 다르게 할 수 있지만 메인 진행과 경제적 가치는 동급으로 유지한다.
- 어느 한 인물이나 길이 사건의 정답을 독점하지 않으며, 서로 다른 관찰과 경험이 함께 이해를 만든다.

## 플레이어의 시작 설정

플레이어는 신에게 구체적인 임무나 명령을 받은 영웅으로 시작하지 않는다. 설명하기 어려운 **부름**을 느껴 여행을 시작하고, 그 부름을 따라 현재의 시작 마을에 도착한다.

플레이어 자신도 부름의 이유, 이 마을로 온 이유, 신이 무엇을 원하는지 아직 알지 못한다. 처음부터 세계를 구할 선택받은 영웅으로 확정하지 않으며, **왜 플레이어가 이곳으로 이끌렸는가**를 장기 메인 스토리의 미스터리로 남긴다.

## 1장 초반 메인 퀘스트

### Main 01 — 부름이 닿은 곳

플레이어가 시작 마을과 기본 NPC 상호작용에 익숙해지는 구간이다.

- 시작 마을 도착 및 마을 둘러보기
- 주민 대표와 대화
- 최근 몬스터들이 평소보다 마을 가까이 나타난다는 이야기 확인
- 남문 경비병에게 상황 확인

강제 전투는 없다. 남문 경비병은 평소 초원 안쪽에서 활동하던 몬스터가 최근 길과 마을 가까이까지 내려온다는 사실을 알려 준다.

- `QuestId`: `main_01_call_reaches`
- 진행: 주민 대표 대화 → 남문 경비병 대화 → 완료
- 시작 방식: 별도 수락 창 없이 주민 대표의 대사를 끝까지 들으면 자연스럽게 Active가 된다.
- 보상: EXP 0, 탈렌트 0, 아이템 없음. 사건 해결 전의 도입 단계이므로 완료 보상은 지급하지 않는다.
- 완료 뒤 `main_02_grassland_anomaly`가 Available이 된다. Main 02의 실제 목표와 대사는 다음 작업에서 구현한다.

### Main 02 — 초원의 이상

목표는 마을 남쪽 초원을 조사하는 것이다. 조사는 단순 오브젝트 클릭이나 몬스터 처치 수 채우기가 아니라 Field 이동, 주변 관찰, 자연스러운 전투와 흔적 확인으로 구성한다.

- `Field_01` 이동
- 초원 입구 주변 조사
- 진행 중 몬스터와 자연 조우 및 첫 메인 스토리 전투
- 초원 안쪽에서 이상한 흔적 확인

첫 단서는 몬스터들이 마을을 공격하려 내려온 것이 아니라 **무언가를 피해 초원 바깥쪽으로 밀려 내려오는 것처럼 보인다**는 정도로 제한한다. 무엇에게 쫓기는지는 확정하지 않는다.

- `QuestId`: `main_02_grassland_anomaly`
- 진행: `field01_main02_investigation_area` 도달 → 지정 조사 조우 `field01_main02_investigation_encounter` 승리 → `field01_main02_tracks` 상호작용
- 일반 처치 수 퀘스트가 아니며, `Field_01`의 지정 `grass_slime_01` 스폰과 연결된 승리만 진행으로 인정한다. 도망·패배는 진행하지 않는다.
- 전투 EXP·탈렌트·Material Loot와 일반 리스폰은 기존 정책을 유지하며, Main 02 자체 완료 보상은 없다.
- 흔적 조사에서는 다섯 Path가 상황을 받아들이는 짧은 표현만 달라지고 정보량·진행·보상은 동일하다.
- 공통 결론은 몬스터들이 마을을 공격하러 온 것이 아니라 무언가를 피해 이쪽으로 밀려온 것으로 보인다는 데까지다. 원인은 확정하지 않는다.
- 완료 뒤 `main_03_unfamiliar_companion`이 Available이 된다. Main 03의 실제 목표와 태온·미엘 등장은 다음 작업에서 구현한다.

### Main 03 — 낯선 동행 (가칭)

- 플레이어와 태온의 첫 만남
- 현장에서 이상 행동을 조사 중인 태온과 상황에 따라 함께 전투
- 전투 후 함께 조사
- 다른 사람을 돕고 있는 미엘과 조우

태온과 미엘은 구조를 기다리는 수동적 인물로 처음 등장하지 않는다.

### Main 04 — 세 사람 (가칭)

- 플레이어, 태온, 미엘이 함께 이동
- 세 사람의 첫 파티 전투
- 3인 파티 구조를 이야기 흐름 안에서 자연스럽게 경험
- 각자의 관찰을 합쳐 추가 단서 확보

### Main 05 — 돌아온 세 사람 (가칭)

- 시작 마을 귀환
- 남문 경비병에게 보고
- 주민 대표에게 조사 결과 전달
- 첫 메인 퀘스트 체인 완료 보상
- 태온과 미엘의 정식 동료 합류
- 다음 지역 또는 `Field_02`로 이어지는 단서 제시

다음 단서는 초원 너머 숲에서도 비슷한 일이 벌어지고 있다는 정도로 둘 수 있다. 구체적인 사건과 대사는 후속 설계에서 확정한다.

## 태온

- 직업: 수호자
- 길: 지적의 길
- 전투 특성: 패턴 익히기
- 핵심 이미지: **관찰 → 이해 → 보호**

태온은 반복되는 행동을 관찰하고 자기 방식으로 규칙과 패턴을 이해하며, 그 이해를 다른 사람을 보호하는 데 활용할 수 있다. 이는 태온의 여러 특징 중 하나이며 `지적 장애 = 특정 성격`으로 단순화하지 않는다.

첫 등장 때 태온은 위험에 빠져 구조를 기다리는 인물이 아니라 몬스터의 이상 행동을 직접 조사한다. 몬스터가 같은 방향을 피한다는 식의 관찰은 캐릭터 방향 예시일 뿐 확정 대사가 아니며, 태온이 항상 더 좋은 정보를 얻거나 정답을 독점한다는 뜻도 아니다.

## 미엘

- 직업: 치유사
- 길: 마음의 상처
- 전투 특성: 회복탄력

미엘은 과거에 힘든 일을 경험했을 수 있지만 그 경험이 정체성 전체를 결정하지 않는다. 주저하거나 두려워하고 힘들어할 수 있으며, 그 뒤 다시 행동하고 관계를 이어 가는 과정이 회복탄력이라는 주제와 연결될 수 있다.

첫 등장에서는 플레이어에게 구조되기만 하는 인물보다 이미 현장에서 다른 사람을 돕고 있는 모습을 우선한다. 자신도 다쳤지만 다른 사람을 먼저 데려가 달라고 말하는 장면은 캐릭터 방향 예시이며 확정 대사가 아니다.

## 첫 사건에서 세 사람이 기여하는 방식

- 플레이어는 현장에서 이상한 흔적을 발견한다.
- 태온은 몬스터의 반복 행동과 이동 패턴에서 이상을 발견한다.
- 미엘은 피해자나 몬스터의 상태를 직접 본 경험을 통해 단순한 공격 행동이 아닐 가능성을 보탠다.

세 사람의 정보가 합쳐져 몬스터들이 마을을 습격하려는 것이 아니라 무언가에게 쫓기고 있을 수 있다는 첫 가설에 도달한다. 어느 한 사람도 정답을 독점하지 않는다.

## 첫 퀘스트 체인의 게임 디자인 목적

별도 튜토리얼 메뉴 대신 이야기 진행으로 기본 시스템을 경험하게 한다.

`이동 → NPC 대화 → 퀘스트 수락·진행 → Field 이동 → 전투 → 조사 → 동료 조우 → 파티 전투 → 마을 귀환 → 퀘스트 보고 → 보상`

완료 보상은 EXP, 탈렌트, 회복약 등 소량의 아이템 방향만 기록한다. 구체적인 수치는 확정하지 않는다.

## 퀘스트 시스템 기반 구현 정책

- `QuestId`와 `ObjectiveId`는 저장과 시스템 연결에 사용하는 안정적인 ID다. 표시 이름, NPC 이름, GameObject 이름은 저장 키나 진행 조건으로 사용하지 않는다.
- 메인 퀘스트는 한 번에 하나만 Active인 직렬 진행을 기본으로 하며, 완료한 선행 QuestId를 통해 다음 메인 퀘스트가 Available이 된다.
- 서브 퀘스트는 서로 독립적이며 여러 개를 동시에 Active로 둘 수 있다.
- 목표는 기본적으로 배열 순서대로 진행한다. 향후 병렬 목표 확장을 막지 않되 현재는 복잡한 분기 그래프를 만들지 않는다.
- 초기 목표 유형은 NPC 대화, 장소 도달, Encounter 승리, 상호작용, 범용 신호다. 관련 시스템이 stable ID를 `QuestService`의 Notify API로 전달하며 매 프레임 Scene을 검색하지 않는다.
- 완료 보상은 기존 `RewardBundle`의 EXP·탈렌트·ItemRewards를 재사용하고, 완료된 퀘스트에는 같은 신호가 반복되어도 다시 지급하지 않는다.
- Save에는 Active QuestId, Completed QuestId, 목표별 진행 횟수, 추적 QuestId를 기록한다. 기존 Version 1 Save에 Quest 필드가 없으면 빈 상태로 복원한다.
- World HUD는 추적 중인 목표 하나만 `[메인]` 또는 `[서브]` 텍스트와 함께 표시한다. 메인 퀘스트 시작 시 기본 추적하며, 향후 사용자가 추적 대상을 바꿀 수 있는 API를 제공한다.
- 대화·상점·인벤토리 Modal 중에는 기존 `WorldModalState` 정책에 따라 Quest HUD도 숨긴다.
- NPC Quest Marker는 stable NPC ID와 현재 퀘스트 상태를 연결한다. `Available`은 `✦ 새 이야기`, `ActiveObjective`는 `◆ 현재 목표`, `ReadyToTurnIn`은 `✓ 완료 보고`, `None`은 숨김으로 표시한다.
- WoW의 `!`/`?`를 복제하지 않으며, 서로 다른 기호와 짧은 텍스트를 함께 써 색상만으로 상태를 구분하지 않는다. Nameplate Y 1.02와 Interaction Prompt Y 1.48 위의 Y 1.92에 배치한다.
- Marker Presenter는 NPC 활성화 시 한 번과 `QuestService.Changed` 사건 때만 갱신한다. NPC별 `Update()`에서 전체 Catalog를 순회하지 않는다.
- 길은 진행 조건이나 보상의 우열을 만들지 않는다. 향후 같은 퀘스트 안에서 `PathId`에 따른 장면·대사 표현만 달리할 수 있다.

## Quest Log UI 정책

- 월드 화면에는 퀘스트 목록이나 현재 목표를 상시 고정하지 않는다. 퀘스트 시작·목표 갱신·완료 때만 약 4초 동안 짧은 Toast를 표시한다.
- 키보드 `Q`와 게임패드 View/Back 계열 메뉴 버튼으로 Quest Log를 Toggle한다. 현재 Unity Input System의 실제 경로는 `<Gamepad>/select`이며, 확인은 기존 Submit, 닫기는 `Q`·`Esc`·게임패드 Cancel을 사용한다.
- Quest Log 왼쪽에는 `[메인 퀘스트]`와 `[서브 퀘스트]` Section 아래 제목 목록만 표시한다. 오른쪽에는 선택한 QuestDefinition의 이름·유형·설명·현재 Objective·진행 단계·정의된 보상을 표시한다.
- Active Main이 있으면 기본 선택하고, 없으면 첫 Active Side를 선택한다. Active Quest가 없으면 `진행 중인 퀘스트가 없습니다.`를 표시한다. 완료 기록과 기존 조회 API는 유지하며 완료 목록 UI는 후속 작업으로 둔다.
- Quest Log는 `WorldModalState`를 사용하는 Modal이다. 열려 있는 동안 플레이어 이동과 World HUD를 잠그며 Dialogue·Shop·Inventory와 동시에 열리지 않는다. 열린 상태나 선택 Index는 Save에 추가하지 않는다.
- 제목 행은 Active Quest 수만큼 동적으로 생성하고 긴 목록은 ScrollRect로 탐색한다. 선택 표시는 색상과 `▶` 기호를 함께 사용하고, 방향키·D-pad·Left Stick·Tab으로 마우스 없이 이동할 수 있다.
- NPC 머리 위 Quest Marker는 목적지 안내 역할이므로 유지한다. Quest Log는 현재 가진 Quest의 내용 확인, NPC Marker는 다음 대화 위치 안내를 담당한다.

Quest Log와 Toast에 사용하는 초기 목표 문구는 다음과 같이 구체적인 행동을 지시한다.

- Main 01: `주민 대표와 대화하세요.` → `남문 경비병과 대화하세요.`
- Main 02: `초원 안쪽의 조사 지점으로 이동하세요.` → `조사 지점 주변의 몬스터 무리를 물리치세요.` → `전투 지점 너머의 흔적을 조사하세요.`

## 대화 초상화와 캐릭터 애셋 제작 정책

- 대화 초상화는 표시 이름이 아니라 NPC/동료의 stable ID로 연결한다. 실제 이미지는 `DialoguePortraitDefinition`의 Sprite만 교체하고 대화 코드나 Save 데이터는 변경하지 않는다.
- Sprite가 아직 없거나 참조가 끊긴 인물은 초상화 프레임과 전용 여백을 모두 숨기고 기존 글자 중심 대화를 그대로 제공한다.
- 메인 초반 서사의 핵심 인물인 태온과 미엘의 초상화를 가장 먼저 제작한다. 이어 Main 01과 귀환 보고에 등장하는 주민 대표와 남문 경비병의 초상화를 제작한다.
- 태온·미엘은 초상화 다음으로 전투 애셋을 우선 제작한다. 첫 동행과 파티 전투에서 서사 표현과 전투 표현이 같은 인물 디자인을 공유하도록 하되, 최종 디자인은 별도 캐릭터 아트 확정 뒤 연결한다.
- 일반 주민과 상점·치유소 등 생활 NPC는 기능과 대화 가독성을 먼저 유지하며, 고유 초상화 제작은 핵심 NPC 뒤로 둔다.

제작 우선순위는 다음과 같다.

1. 초상화 시스템
2. 태온·미엘 초상화
3. 주민 대표·남문 경비병 초상화
4. 태온·미엘 전투 애셋
5. 나머지 NPC

Main 01과 Main 02의 실제 데이터·Scene 연결이 구현되었다. 다음 구현 대상은 Main 03 「낯선 동행」의 실제 목표와 인물 등장이다.

## 주요 캐릭터 설계 원칙

주요 NPC도 플레이어와 마찬가지로 직업과 길을 별개의 축으로 다룬다.

- 직업: 전투에서 무엇을 하는가
- 길: 삶과 세계를 어떤 방식으로 경험해 왔는가

길을 전투 패시브로만 끝내지 않고 이야기와 캐릭터 경험에도 자연스럽게 연결하되, 장애에 대한 고정관념이나 성격 분류표로 사용하지 않는다.

- 몬스터들이 무엇에게 쫓기는지에 대한 정답
- 배후 세력, 최종 악역과 Story Boss

- 부름의 정체와 신의 구체적인 의도
