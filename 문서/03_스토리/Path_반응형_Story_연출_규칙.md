# Path 반응형 Story 연출 규칙

> 2026-09-30 확정 설계 정본. 향후 Story 전반에 적용한다. 기존 Runtime에 일괄 적용했다는 뜻이 아니며 기존 장면 변경은 별도 설계·구현·검증 작업이다.

## Player Agency First

Path는 능력치 선택뿐 아니라 세상을 관찰하고 문제를 이해하며 어떤 정보에 먼저 반응하는지에 영향을 준다. 장면이 플레이어의 Path와 직접 관련되면 플레이어를 감지·관찰·패턴 발견·문제 제기·첫 판단의 우선 주체로 둔다. 같은 Path의 Companion이 있어도 플레이어를 구경꾼으로 만들지 않는다. 플레이어가 발견자라면 Companion은 교차 확인·보완·경험에 따른 해석·추가 정보 제공을 맡을 수 있다. 전문성은 무조건 먼저 알아내는 순서로 표현하지 않는다.

관련 Path가 없는 플레이어에게는 Companion 또는 Story NPC가 필요한 정보를 발견하고 공유한다. 어떤 Path도 핵심 정보·정답·Main Quest 진행을 독점하지 않는다. 특정 Path가 없다는 이유로 필수 정보가 영구 누락되거나 진행이 막혀서는 안 된다. 분기는 결과의 획득 가능성보다 누가 어떤 방식으로 먼저 알아내는지를 바꾼다.

## 공통 Story State와 분기 범위

대부분의 Main Quest는 분기 후 동일한 핵심 사실·Quest 목표·완료 상태로 수렴한다. 예를 들어 Hearing 플레이어 발견→세린 확인과 세린 발견→파티 확인 모두 반복적인 지면 진동이라는 정보를 얻는다. 발견자·관찰 문구·조사 방식·선택 대사·Companion 반응·짧은 관계 표현을 우선 분기한다. Path별 Main Quest 전체·Dungeon·필수 Boss·독점 보상·큰 콘텐츠 분량 차이는 피한다.

Story State나 Quest 진행의 차이가 필요한 예외는 장면 문서에 내용과 이유를 명시하고 별도로 확정한다. 이 규칙 자체가 새로운 Quest Graph나 전투 효과를 허가하지 않는다. Path와 직업의 독립성·추천 외 조합 허용은 [Path 시스템](../02_세계관/Path_시스템.md)을 유지한다. 관련성이 없는 장면은 `관련 Path: 없음`으로 쓰며 모든 대사에 분기를 강요하지 않는다.

## Hearing 플레이어와 세린

청각의 길을 소리를 잘 듣는 능력으로 설명하지 않는다. 일반적인 방식으로 소리를 듣지 못할 수 있으며 보조 장치와 자신에게 익숙한 감각·신호 해석으로 사람의 말·진동·방향·반복·주변 변화를 파악한다. 장치는 인식 가능한 형태로 신호를 변환하는 도구이고 모든 판단을 대신하지 않는다. 의미를 판단하는 주체는 경험·관찰·해석을 하는 사람이다.

Hearing 플레이어는 먼저 또는 세린과 거의 동시에 신호를 감지하고 **첫 관찰을 제시**한다. 세린은 자신의 장치·경험으로 교차 확인하고 필요하면 세부 패턴을 해석한다. 플레이어가 “진동하고 재가 움직이는 간격이 같아요.”라고 관찰하면 세린은 “저도 그렇게 잡혀요.”라고 확인하고 더 약한 반복 신호나 아직 알 수 없는 인과관계를 보완할 수 있다. 세린의 숙련된 조사자 역할을 없애지 않는다.

그 외 플레이어에게는 세린이 먼저 관찰을 공유할 수 있다. 이때도 플레이어는 질문·다른 단서와 비교·조사 결정에 참여한다. 세린이 영구 명단에 있으나 현재 전투 편성에서 제외됐어도 핵심 정보 획득을 막지 않는다. 필요한 장면에는 현장 Story NPC 또는 기존 Story Override를 검토하되 저장된 Permanent Party·Formation은 보존한다. 대화 참여를 이유로 전투 파티를 무조건 세린으로 교체하지 않는다.

같은 Path끼리 잠시 동시에 멈추거나 “설명할 필요가 적어서 편하네요.” 같은 짧은 일상적 공감을 표현할 수 있다. 장치 인식·신호 확인을 통해 자연스럽게 관계를 보여 주며 같은 길을 선언하는 설명이나 감동·극복 연출을 필수로 삼지 않는다. 같은 장애를 가진 사람도 감각·장치·생활 경험이 다를 수 있다.

## 다른 네 Path의 확장 방향

| Path | 개별 장면에서 검토할 관점 | 표현 경계 |
| --- | --- | --- |
| Vision / 시각 | 다른 감각·기억·공간 구조·반복 배치·주변 변화 | 아무것도 못한다거나 초능력으로 더 잘 본다고 표현하지 않는다. 대표 Story Mechanic은 추후 설계한다. |
| Intellectual / 지적 | 익숙한 방식으로 규칙·순서·구조·반복·이전 사건과 공통점 정리 | 장애의 보상으로 천재적 분석을 하는 설정을 만들지 않는다. |
| Mobility / 지체 | 경사·폭·바닥·접근 가능한 경로·구조물 이용 방법 | 불편 호소·진행 방해 전용 역할로 만들지 않는다. 이동 경험을 환경을 읽는 관점으로 쓴다. |
| Emotional Scar / 마음의 상처 | 말과 행동의 차이·회피·긴장·주저함·관계 변화에 대한 조심스러운 관찰 | 마음을 마법처럼 읽거나 상처가 있으니 모두 이해한다고 단정하지 않는다. |

각 행은 관점 수준의 방향이며 감지 범위·새 능력·전용 보상·정확한 Mechanic을 확정하지 않는다. 플레이어 우선과 공통 핵심 정보 원칙은 모든 Path에 동일하게 적용한다.

## 접근성과 표현 검토

장애를 연민의 대상·극복해서 특별해진 원인·초능력의 보상으로 쓰지 않는다. 보조 장치가 장애를 완전히 없애거나 타인이 과도하게 보호하는 장면을 피한다. Path가 성격 전체를 정의하지 않는다. 반응속도를 강요하지 않고 충분한 읽기·선택 시간을 제공하며, 소리·색상만으로 필수 단서를 전달하지 않는다. Hearing 분기의 정보도 자막·관찰·장면 서술로 전달한다.

## Story 작성과 Voice 제작 순서

장면 작성은 [Story Scene 설계 템플릿](Story_Scene_설계_템플릿.md)의 Path-Reactive Check를 사용한다. 제작 순서는 **Story 확정 → Path Branch 확정 → Dialogue ID 확정 → TTS Manifest → Voice 생성 → Unity 연결**이다. 먼저 Voice를 생성한 뒤 대사를 분기시키는 순서는 피한다. 변경이 필요한 기존 대사·음성은 별도 수정 목록과 재검수 범위를 확정한다.

서로 다른 Path 분기의 대사는 서로 다른 Stable Dialogue ID를 사용한다. `main16_ash_hearing_player_01`, `main16_ash_default_serin_01`은 의미를 보여 주는 예시이며 실제 Naming Convention·최종 ID는 구현 전 LOCAL 기준으로 확정한다. 분기 간 같은 ID/Clip을 덮어쓰지 않고, 각 ID의 Speaker·본문·선택 조건을 Manifest와 대조한다. Story State가 같아도 Dialogue ID를 공유해야 한다는 뜻은 아니다.
